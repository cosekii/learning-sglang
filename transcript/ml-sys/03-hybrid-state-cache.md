## Prose · Where this chapter's claims come from

Step 1 selects two rows from the six-setting experiment in `Awesome-ML-SYS-Tutorial/engineer/hybrid-prefix-cache/readme.md:572-599`. The same machine, system prompt and short requests were used while `num_batch` changed. At 1024, the short request took 3.95 s and recomputed 1019–1029 tokens; at 64, it took 0.91 s and recomputed 63–69 tokens. Cold startup took 16.9 s and 28.4 s respectively. These are the article's measurements, not measurements from this computer or a universal recommendation.

Step 2 uses the article's simplified 5,500-token system and 40-token user example (`readme.md:71-89`). Full-attention K/V is per-token and append-only, so the new request can retain the 5,500 shared slots, release the old tail and prefill 40 new tokens. The block widths are schematic. Ch. 8 Steps 2–3 already established shared pages and longest-common-prefix matching.

Step 3 follows `readme.md:93-135`: a recurrent layer keeps a fixed-size state and updates it rather than storing every earlier state. The pinned llama.cpp source says that Mamba-like models do not preserve previous per-token states (`llama-memory-recurrent.cpp:170-172` at `7e4c0a96880dae4fc4268ad441f8a6446bd5460a`). Its optional bounded snapshot ring is a separate exception, not evidence that an arbitrary earlier state is always available.
