## Prose · Where this chapter's claims come from

Step 1 counts the shipped startup shapes. Text-only mode defines six stages in one `pipeline` process on one GPU and still accepts multimodal input (`sglang_omni/models/qwen3_omni/config.py:136-147,257-265,412-422`; `docs/cookbook/qwen3_omni.md:46-57`). Default speech defines seven stages, each in its own process: image encoder, audio encoder, thinker and code2wav use GPU 0, talker uses GPU 1, and preprocessing and decode are CPU stages (`config.py:268-318,425-452`). These counts exclude the HTTP server and coordinator.

Step 2 separates server mode from requested output. Both modes accept multimodal input (`docs/cookbook/qwen3_omni.md:206-208`). Text-only joins active input branches at `mm_aggregate`; the speech thinker merges them itself (`sglang_omni/models/qwen3_omni/config.py:136-189,212-254`). A speech request with `modalities: ["text"]` terminates at decode and excludes talker; adding `"audio"` also terminates at code2wav (`sglang_omni/models/qwen3_omni/request_builders.py:200-261`; `tests/unit_test/qwen3_omni/test_pipeline.py:898-930,1935-1947`). The public default is text output, and a text-only server returns no audio when audio is requested (`docs/basic_usage/omni.md:154-170,199-200,386-395`).

Step 3 uses the public placement experiment from Chapter 8 Step 1. At concurrency eight, moving only the talker from the thinker's GPU to its own reduced mean-of-two p90 first sound from 2.680 to 1.439 seconds, about 46%. Code2wav stayed beside the thinker in both arms. The same guide reports a separate single-stream result: isolation improved first sound but increased end-to-end latency by 14–17%, so the chapter does not turn one metric into a universal rule (`docs/cookbook/qwen3_omni/tuning.md:52-69`).
