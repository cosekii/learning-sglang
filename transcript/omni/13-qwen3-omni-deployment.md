## Prose · Where this chapter's claims come from

Step 1 counts the shipped startup shapes. Text-only mode defines six stages in one `pipeline` process on one GPU and still accepts text, image, audio or video input (`sglang_omni/models/qwen3_omni/config.py:136-147,257-265,412-422`; `docs/cookbook/qwen3_omni.md:46-57,206-208`). Default speech defines seven stages, each in its own process: image encoder, audio encoder, thinker and code2wav use GPU 0, talker uses GPU 1, and preprocessing and decode are CPU stages (`config.py:268-318,425-452`). These counts exclude the HTTP server and coordinator.

Step 2 separates server mode from requested output. Both modes accept multimodal input (`docs/cookbook/qwen3_omni.md:206-208`). Text-only joins active input branches at `mm_aggregate`; the speech thinker merges them itself (`sglang_omni/models/qwen3_omni/config.py:136-189,212-254`). A speech request with `modalities: ["text"]` terminates at decode and excludes talker; adding `"audio"` also terminates at code2wav (`sglang_omni/models/qwen3_omni/request_builders.py:200-261`; `tests/unit_test/qwen3_omni/test_pipeline.py:898-930,1935-1947`). The public default is text output, and a text-only server returns no audio when audio is requested (`docs/basic_usage/omni.md:22,154-170,199-200,359,386-395`).

Step 3 preserves the public PR #1235 topology from Chapter 8 Step 1: H200s, thinker TP2 across GPUs 4 and 5, and code2wav with the thinker process on GPU 5. At concurrency eight, moving only the talker from thinker GPU 4 to its own GPU 2 reduced mean-of-two p90 first audio from 2.680 to 1.439 seconds, about 46%. The exact raw values come from PR #1235; the pinned tuning guide publishes rounded ranges and a separate single-stream result where isolation improved first audio but increased end-to-end latency by 14–17% (`docs/cookbook/qwen3_omni/tuning.md:52-69`). Step 8's TP1 plan is a different topology and needs its own comparison.

Step 4 starts with the H100 BF16 colocated config's declared `2 + 2 + 78 + 10 + 2 = 94%` (`examples/configs/qwen3_omni_colocated_h100_bf16.yaml:1-20`). The thinker factory defaults `encoder_mem_reserve` to 0.05. With no explicit `thinker.engine.mem_fraction_static`, it subtracts five whole-card percentage points before deriving the AR budget, giving `0.78 − 0.05 = 0.73`; this reserve is headroom for encoder work outside thinker AR, not the separate 2% + 2% encoder stage declarations (`sglang_omni/models/qwen3_omni/stages.py:155-215,1230-1243,1358-1373`; `sglang_omni/scheduling/sglang_backend/server_args_builder.py:176-210`). A matching explicit fraction skips the reserve, a conflicting fraction is rejected, and a byte-sized KV declaration skips the fraction adjustment (`tests/unit_test/qwen3_omni/test_sglang_ar_budget.py:491-511,540-562`; `stages.py:1384-1402`). Colocation requires one common GPU, TP 1, no in-worker process replicas and a declared budget for every GPU stage (`sglang_omni/models/qwen3_omni/placement.py:55-60,84-108,122-187`). These are configuration arithmetic and validation rules, not measured occupancy.

Step 5 compares BF16, FP8 and INT4. The compatibility matrix permits each precision for text-only output, separate thinker/talker cards at TP1 or TP2, or one shared card at TP1 (`docs/cookbook/qwen3_omni.md:25-44`). BF16 is the default. The FP8 checkpoint supplies precision config for thinker and talker AR; `--dtype fp8` is not the selection mechanism (`docs/cookbook/qwen3_omni.md:153-169`; `sglang_omni/models/weight_loader.py:19-42`). The INT4 checkpoint quantizes the thinker transformer layers with 4-bit quantization and group size 128, while talker AR and code2wav remain BF16 (`docs/cookbook/qwen3_omni.md:181-195`). The cookbook explicitly names code2wav's BF16 precision for INT4. The implementation also defaults omitted code2wav `dtype` to BF16 for the other rows (`sglang_omni/models/qwen3_omni/components/code2wav_scheduler.py:146-154,1230-1260`; `sglang_omni/models/weight_loader.py:19-26`). The approximately 60, 40 and 30 GB values and their 50%/25% reductions appear in a single-GPU H100/H20 section, but their exact quantity—weights alone, loaded stages, runtime peak or whole-server footprint—is unstated. They are not measured per-card budgets or local footprint, latency or quality measurements (`docs/cookbook/qwen3_omni.md:196-200`).

Step 6 applies the shipped replica2 config. The thinker defaults to 64 running requests; each talker engine defaults to 32 (`sglang_omni/models/qwen3_omni/stages.py:1276-1286`; `sglang_omni/models/qwen3_omni/config.py:37,454-496`). Two talker replicas make each code2wav process compute `codec_state_slots = 32 × 2 = 64` for its own independent pool, covering the streams the talkers can run (`config.py:468-476`; `tests/unit_test/qwen3_omni/test_colocation_config.py:177-203`; `sglang_omni/models/qwen3_omni/components/code2wav_scheduler.py:1284-1299`). A full pool falls back to stateless left-context decoding instead of rejecting the stream (`code2wav_scheduler.py:296-314`). The config places talker/code2wav replica 0 on GPU 1 and replica 1 on GPU 2, with `12.3% + 1.4% = 13.7%` declared per replica GPU (`examples/configs/qwen3_omni_speech_replica2.yaml:1-42`). This is per-process configuration capacity, not one deployment-wide pool, a throughput measurement or a binding-contract guarantee under a custom replica policy.

Step 7 separates health from performance. Readiness sends a small image, one second of audio and a short instruction, with at most eight new tokens per token-generating stage (`docs/cookbook/qwen3_omni.md:202-204`; `sglang_omni/models/qwen3_omni/config.py:328-366`). Video, large batches and other input sizes may still warm later (`docs/basic_usage/omni.md:345-349`). A comparison first resolves the config, then holds input, sampling, hardware and warmup fixed while changing one deployment choice (`docs/basic_usage/process_topology.md:52-53`; Ch. 8 Steps 6 and 8). The documented sweep `--concurrencies 1,16 --repeats 5 --generate-only` gives ten measured runs per arm; per-run raw results, failures and memory stay in the comparison. The benchmark client measures first-audio and total-request wall time, separate from listener playback stalls and the Ch. 12 stop/response clocks (`benchmarks/metrics/performance.py:27-31`; `benchmarks/eval/benchmark_omni_seedtts.py:371,398,408`). The shipped summary provides first-audio median, p95 and p99; Step 8's p90 is a custom reduction of non-null `per_request.audio_ttfp_s` values (`benchmarks/metrics/performance.py:219-223,480`). The benchmark notes that p99 needs at least 100 measured requests in the sample, not merely a particular number of runs (`benchmarks/README.md:249-288`; `benchmarks/eval/benchmark_omni_seedtts.py:504-505,552-561`). Generate-only does not transcribe audio or compute WER or speaker similarity, so Ch. 8 Step 8's quality checks run separately (`benchmarks/README.md:215-220,659`).

Step 8 constructs one TP1 starting hypothesis for eight concurrent spoken requests: default BF16 speech, text and audio output, input encoders, thinker and code2wav on GPU 0, and talker alone on GPU 1. This is motivated by Step 3's different H200/TP2 evidence. The local A/B holds that two-GPU layout fixed and compares the default BF16 checkpoint with the native FP8 checkpoint, changing only checkpoint precision. Eight is below the 32-request talker cap, leaving `32 − 8 = 24` requests of headroom, so the example does not add a replica before measuring a queue. The evidence row uses target concurrency 8 and keeps first-audio median and custom p90, total time, stalls, failures, memory, output quality and per-run raw results; Ch. 8 Step 8 names the completion, word-error and voice-match checks outside the generate-only sweep, and interruption tests also keep the Ch. 12 listener clocks.
