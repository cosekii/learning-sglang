## Prose · Where this chapter's claims come from

Step 1 follows the shipped three-stage route in `sglang_omni/models/fishaudio_s2_pro/config.py:23-67` and `stages.py:522-552`. The first non-final streaming window opens at 40 frames (`streaming_vocoder.py:43-66`; `scheduling/audio_stream.py:86-102`). A request ending with fewer frames still decodes through the final flush (`scheduling/audio_stream.py:106-148`). Each generated frame carries one semantic code and nine remaining codes for the vocoder, so the constructed product is 40 × 10 = 400 codes chosen from codebooks (`sglang_model.py:418-510`; `payload_types.py:35-50`). One codec frame represents 2,048 samples at 44,100 Hz (`fish_speech/configs/modded_dac_vq.yaml:3-29`; `fish_speech/models/dac/modded_dac.py:885-913,928-988`). The resulting 1.858 seconds describes represented audio, not elapsed latency.

Step 2 follows `sglang_omni/models/fishaudio_s2_pro/stages.py:249-376,425-490`: reference audio becomes mono, resamples to 44,100 Hz and enters the reference DAC. The constructed one-second clip starts at 16 kHz. The DAC's 2,048-sample codec frame gives `ceil(44,100 ÷ 2,048) = 22` frames and 956 padding samples. The output has ten rows. `scheduling/reference_encoder.py:344-413` caches matching reference codes on CPU and returns copies; this cache is not AR KV. Already supplied `vq_codes` bypass encoding, and a request without references omits this voice prompt.

Step 3 follows `sglang_omni/models/fishaudio_s2_pro/tokenizer.py:53-73,94-162` and `model_runner.py:288-356`. Slow AR is the outer, time-axis loop. Target text uses ordinary tokens. Each reference frame contributes a semantic token made from code 0, while all ten code rows modify the model input at that position. The exact embedding average is `(text embedding + ten codec embeddings) ÷ sqrt(11)`, from `fish_speech/models/text2semantic/audio_decoder.py:597-612`. Multiple references concatenate along time; a request without references omits the system voice block.

Step 4 follows a nonterminal frame in `sglang_omni/models/fishaudio_s2_pro/sglang_model.py:294-300,418-510`. Fast AR is the inner loop. Call 0 receives the projected Slow hidden state and does not supply a vocoder code. Calls 1–9 choose the nine remaining codes by argmax. The engine stores both the raw Slow `semantic_token` and its derived `sem_id` (code 0), plus those nine codes: 11 rows. `streaming_vocoder.py:88-106` drops the raw token and sends the other ten rows to the vocoder. The 1+9=10 Fast-call count has no eleventh call after code 9.

Step 5 follows `model_runner.py:62-100,148-191` and `sglang_model.py:365-382,484-488`. The previous frame's raw token and all ten DAC codes feed the next Slow input. Slow KV retains the prompt and earlier frames through SGLang, and `model_runner.py:324-344` applies `req.prefix_len`. `request_builders.py:65-78,160-168` makes `extra_key` fingerprint all ten reference code rows, preventing different reference voices from sharing radix KV merely because code 0 matches. Requests with the same references and cached prefix can reuse that common prefix even when their target suffixes differ; a match does not guarantee that the KV is still cached. Fast KV covers positions 0–9 inside one frame and resets before the next Slow output (`fish_speech/models/text2semantic/audio_decoder.py:394-411,505-526,547-595`). Reference-code caching from Step 2 is a separate CPU artifact cache.

Step 6 follows `model_runner.py:48-76` and `request_builders.py:148-167,192-202,233-248`. EOS is `<|im_end|>`: Fast AR still runs for that Slow output, but the collector drops the terminal frame. Earlier accepted frames remain. An immediate EOS leaves no audio codes and produces an error instead of empty audio. Length exhaustion retains accepted frames with `finish_reason="length"`. The effective cap is `min(request max, 2048, max(4096−1−prompt tokens,1))`; the request default is 1,024 (`payload_types.py:35-50`). Abort suppresses pending chunks and terminal success output and clears stream state. It cannot recall chunks already delivered.

Step 7 uses a constructed 90-frame stream through `scheduling/audio_stream.py:65-148,151-239,242-333`. The shipped rules open at 40 frames, later take 20 old frames plus up to 45 new ones, and hold a 512-sample sound tail for crossfading. The three calls therefore read 40, 65 and 25 frames. Their emitted samples close to `90 × 2,048`. Each non-final call holds a fresh 512-sample tail. The next call crossfades the previous tail and holds its own; the final flush releases the last tail. The old frames and tail join windows; they are not Qwen-style retained neural codec state. `request_builders.py:276-298` and `scheduling/audio_vocoder.py:116-182` avoid a second full-request decode after streamed audio exists.

Step 8 follows `scheduling/audio_vocoder.py:194-224` and `scheduling/streaming_simple_scheduler.py:311-390,434-480`. Non-streaming requests finish Dual-AR first, then batch their `[11,T]` results. The vocoder drops the raw row, pads to the longest request and trims each output back to its own length. The two constructed requests have 90 and 40 frames, so their padded call is `[2,10,90]` and request B has 50 padding frames. The shipped collector allows at most eight completed requests and waits up to 2 ms for additional requests. Step 7's streaming chunks remain per request. Delivery scheduling changes no Dual-AR choices. The closing session question belongs to Chapter 12.
