## Prose · Where this chapter's claims come from

Step 1 reads the term and its parts. A term is `store.Term`: `Term`, `Aliases`, `Note`, `Enabled`, timestamps. `Clean` trims each to one line, drops empty aliases, the term itself and case-insensitive duplicates, and keeps at most `MaxAliases = 10`; `Check` refuses an empty term, a newline, or more than `MaxTermChars = 80` runes (`dict.go`).

Step 2 reads the four destinations and their switches. A row's `store.Term.Note` is private and is not sent anywhere (`internal/store/store.go:215-230`). `SpeechHints` returns `dict.Hints` only when `Dictionary.Enabled && Dictionary.ASRHints` (`session/run_audio.go`). `spoken()` replaces aliases only when `Dictionary.Enabled` (`session/cleanup.go`). `glossary()` copies only `Term` and `Aliases` into `compose.Term`, only when `Dictionary.Enabled && Dictionary.Glossary` (`session/run_transcribe.go:110-120`). The separate dictionary-wide `settings.Dictionary.Notes` goes to `PromptDictionary` only when `Dictionary.Enabled && !NotesOff` (`session/text.go:120-126`).

Step 3 reads `dict.Hints`: it clones the terms, sorts stable by `UpdatedAt` descending, keeps enabled ones once (ignoring case via lower-cased key), and returns each term as one line. Aliases are not included; the doc comment says they are what recognition gets wrong. A downstream service with fewer hint slots drops hints from the end, so the newest-changed terms stay at the front (`dict.go:89-106`).

Step 4 reads `dict.Replace` and `matchText`. Enabled terms' aliases are matched; each end of a Latin alias is boundary-checked only when that end is itself a letter or digit (`wordRune`, `alias.go:187-197`), so an alias ending in punctuation skips that side's check; CJK aliases match anywhere; patterns are sorted longest first; a term already written as itself is kept (it is only added as a pattern when `highlight`). `spoken()` in `session/cleanup.go` calls `dict.Replace(raw, r.terms)` and is called before `transcribe()` in `session/run.go:301,312`.

Step 5 reads `compose.Build`. With at most `GlossaryAllUpTo = 30` distinct terms, all become candidates and the rendered glossary sits in system. With more than 30, only terms or aliases mentioned in the replaced text become candidates; system keeps generic rules and the selected `<glossary>` opens the user message when matches exist (`compose.go:366-377`, `411-416`). In both cases the output is the longest candidate prefix that fits 60 lines and 2000 bytes, stopping at the first over-budget line without truncating it (`compose.go:576-580`). Go's `len(string)` counts UTF-8 bytes; the limit excludes the surrounding tags. The request input is `call Priya.` after alias replacement. An unchanged system prefix may let the provider reuse its prompt cache, with no guaranteed time or token saving (`compose_test.go:574-577`, `595-630`).

Step 6 reads `PromptDictionary` and `addDictionary`: dictionary-wide `settings.Dictionary.Notes`, not a row's private `store.Term.Note`, is trimmed and added as the `dictionary` system layer after the task layers and before scene and glossary (`compose/dictionary.go:11-17`). Final messages are `[system, …history, user]` (`compose.go:253-258`). This request's replaced input sits inside `<input>` in user, never in system (`compose/before.go:13-17`). Notes go neither to ASR nor to `dict.Replace`. This Transcribe example has no history messages.

Step 7 is a status read: `SpeechHints` and `spoken()`/`dict.Replace` do not call the language model; `Glossary` and `addDictionary` are only used when a cleanup request is built.
