## Prose · Where this chapter's claims come from

Step 1 reads one history entry. `store.Entry` holds the kind, created time, status, app, the recognised and delivered texts, and the recording's file name in `Audio` (`Voxt/internal/store/store.go:69`). `session/run.go`'s `keep()` writes that entry and, when `KeepAudio` is on or the recognition failed, writes the WAV and sets `Audio` (`run.go:506`, `run.go:546`). History is kept only when `privacy.keepHistory` is on, which is its default.

Step 2 reads the two defaults: `settings.History` keeps entries for `DefaultKeepDays = 90` days and keeps any count (`Voxt/internal/settings/history.go:28`, `history.go:35`); a recording kept for a retry lasts `DefaultAudioRetention = 7 * 24 * time.Hour` (`Voxt/internal/session/session.go:355`). The second clock exists only when recognition failed or the user cancelled and `KeepAudio` is off (`run.go:583`).

Step 3 reads the age cut: `History.Cutoff` is `now.AddDate(0, 0, -Days())` (`settings/history.go:61`), and `pruneWhere` deletes rows with `created_at < cutoff` (`Voxt/internal/store/sqlitestore/history_retention.go:123`). The clean-up runs at start, after each history change and when the setting changes (`Voxt/history_settings_ops.go:7`).

Step 4 reads the count cut: `Retention.PerKind = History.PerKind()` and `pruneWhere` deletes each kind's rows past the newest N using `ROW_NUMBER() OVER (PARTITION BY kind …)` (`history_retention.go:125`, `history_retention.go:129`). The choices are 0 (no limit), 50, 100, 300, 500 and 1000 (`settings/history.go:35`).

Step 5 reads the retry clock: when a recording is kept only for a retry, `AudioUntil = now + Config.AudioRetention` (`run.go:552`). `expireRecordings` starts at app launch and calls `History.ExpireAudio` every `recordingSweep = time.Hour` (`Voxt/history_retry.go:89`, `history_retry.go:91`). `ExpireAudio` clears `audio` and `audio_until` only where the row still names the same file (`history.go`). A successful retry removes a retry-only recording at once (`Voxt/internal/session/retry.go:82`).

Step 6 reads `Manager.Retry`: it reads the WAV, rejects a missing recording or a file that is not 16 kHz mono (`retry.go:52`, `retry.go:60`), recognises the whole file (`retry.go:157`, `retry.go:175`), runs the feature's language-model step with the current settings, and writes the same entry back (`retry.go:93`). It inserts nothing; its comment says so (`retry.go:38`).

Step 7 reads `historyapi.Row`, which lists the exported fields and says a new `store.Entry` field does not come along by itself (`Voxt/internal/historyapi/row.go:24`). `Walk` filters to finished entries, oldest first (`row.go:57`). `selection` and `typed` appear only when the include-selected-text setting is on (`row.go:47`). The `--day`, `--since`, `--until` and `--format` behaviour is in `Voxt/docs/history-access.md`.

Step 8 reads `history_access_controller.go`: the socket is opened only while `privacy.historyAccess` is on (`syncHistoryAccess`); the read log and the new-program notice are written by the audit hook. `historyapi.Listen` sets mode `0600` (`Voxt/internal/historyapi/server.go:94`), and the docs say the switch is not a boundary against programs running as the same user (`Voxt/docs/history-access.md`).
