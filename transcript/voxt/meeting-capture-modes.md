## Prose · Where this chapter's claims come from

Step 1 reads the mode table. A mode is how the user wants a meeting captured: `meeting` (the default, also `""`), `subtitles` or `recording` (`Voxt/internal/meeting/types.go:18-24`; the default fills in at `manager.go:76-78`). `Sources()` maps them: subtitles takes `[system]`, recording takes `[mic]`, and the default takes `[mic, system]` (`Voxt/internal/meeting/mode.go:6-16`). The Settings labels are "Full meeting (microphone and system audio)", "Subtitles (system audio only)" and "Recording (microphone only)" (`Voxt/settings_meeting_view_state.go:42-46`). One track is 16 kHz mono PCM16 (`Voxt/internal/asr/asr.go:31-32`), so 32,000 bytes a second; one track-hour is 115.2 MB and a full-meeting hour writes two of them.

Step 2 reads the capture wiring. The mic track is `session.HelperAudio{H: sup}` and the system track is the same with `Method: proto.MethodCaptureSystem` (`Voxt/meeting_link.go:43-46`). `capture.system` records the sound the Mac plays through a Core Audio process tap on the default output: every process but the helper and its parent, mixed down to mono, private to the helper and still heard by the user; it sends `capture.started` after the tap starts, so a quiet output can start a meeting (`Voxt/docs/helper-protocol.md:111`).

Step 3 reads the start. `Manager.Start` refuses a second meeting (`manager.go:86-89`, `ErrBusy`), requires 1.5 GiB free (`manager.go:79-84`, `disk.go:5-9`), creates `meetings/<id>/` under the data folder (`manager.go:117-131`, `meeting_link.go:37-38`), and starts one track per source (`manager.go:155-159`). The archive writes `<id>/mic.wav` and `<id>/system.wav` (`archive.go:26-28`) with a 44-byte placeholder header whose lengths are patched when the file closes (`archive.go:75-103`); every PCM chunk goes to `archive.Write` (`track.go:62-74`). A watcher checks free space every 2 s and interrupts the meeting below 0.9 GiB (`disk_watch.go:8-30`, `disk.go:5-9`).

Step 4 reads the system gate. macOS asks for System Audio Recording the first time a tap starts; which refusal status reaches the app has not been observed on a real Mac, so any failure to build the tap currently fails the capture start (`docs/helper-protocol.md:111`). A track that cannot start is a `StartError` (`types.go:156-168`, `track.go:22-28`), and any track failing makes `Start` stop the rest and fail (`manager.go:155-159`, `175-183`): no folder, no files.

Step 5 reads the mode switch. `SetMode` keeps the tracks both modes record, starts the new mode's extra tracks first, and only then stops the tracks only the old mode had (`manager_mode.go:10-16`, `36-41`, `71-73`); if a new track cannot start, the added tracks are dropped and the meeting keeps its old mode (`manager_mode.go:38-44`).

Step 6 reads the retention. Writing and keeping are separate: a finished meeting's folder is deleted right away unless `Privacy.KeepAudio` is on or the mode keeps audio (`finalize.go:480-497`; recording mode always keeps, `mode.go:22-23`). A failed or interrupted meeting with keep-audio off gets `AudioUntil = now + 7 days` (`finalize.go:467-478`), and the hourly sweep — the same `recordingSweep = time.Hour` as Chapter 9 Step 5's retry recordings (`Voxt/history_retry.go:89`, `Voxt/meeting_audio.go:17-58`) — deletes the folder once it is due.

Step 7 reads the labels. A mic segment's speaker is `me` with no model involved (`track_transcribe.go:141-148`, `195-197`). `Diarize()` is true only in full meeting mode (`mode.go:19-20`), and the after-meeting pass runs the diarizer on the system track only (`finalize.go:51-57`, `147-152`); the README names the labels Speaker 1–4 with MOSS-Transcribe-Diarize installed, while the mic side stays Me (`Voxt/README.md:64`). The code sets no hard cap on the speaker count. The same pass re-reads both WAVs with file-mode recognition and replaces the live segments (`finalize.go:30-46`).

Constructed parts: the timestamps and wordings of the example lines (`hi everyone`, `morning all`, …) are invented; the one-hour sizes follow the 32,000 B/s rate. No real meeting, permission dialog, or diarizer was run.
