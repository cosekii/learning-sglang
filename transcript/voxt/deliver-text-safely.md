## Prose · Where this chapter's claims come from

Step 1 reads the `deliver` package comment. The result goes to the app in front now and its focused element, whichever app it is. The start app, `Request.Target`, is the app in front when the shortcut was pressed. It still matters in three ways: its element gets the benefit of the doubt, a selection is replaced only there, and its auto key is pressed only there. If VoxtNew itself came to the front after the start, the start app is activated again first.

Step 2 reads `Secure()` and the `check()` order. `Secure(f)` is true when the focused element's subrole is `AXSecureTextField`. In `check()` the secure test comes before the editable tests, so a password field stops the insert. The paste is not sent; the caller shows the answer card.

Step 3 reads `Writable()` and the rest of `check()`. In the start app, an element counts as writable when it is editable, when Accessibility gave an error, or when its role is not one of the non-text roles (a button, list, table and similar). In another app, the element must report `Editable`; an unknown element there is not enough. A selection replace and VoxtNew's own window also require `Editable`.

Step 4 reads `deliver.go` `DefaultVerifyMS` and `PasteCheck.compare`. `DefaultVerifyMS` is 1000 ms. The helper reads the focused element before ⌘V and after it. `compare` reports changed when the value length, value digest, selection or text marker differs; it reports unreadable when nothing could be compared. In `insert()`, `CheckUnchanged` means `ReasonUnconfirmed`, or `ReasonSecureInput` when another app had secure event input on; a web area container with no secure input is trusted as inserted.

Step 5 reads `helper/Sources/VoxtNewHelper/TextIO.swift`. The paste snapshots the general pasteboard unless `KeepClipboard` is set, writes the text, posts ⌘V, and reads the field while `VerifyMS` allows. The old clipboard returns 150 ms after a confirmed insert, or after `RestoreDelayMS` (default 500) when the outcome is unknown. Before restoring it checks `changeCount`; if another program wrote meanwhile, it does not overwrite that write. When nothing was inserted, the session opens the answer card, which offers Insert and Copy and keeps the text on the clipboard.
