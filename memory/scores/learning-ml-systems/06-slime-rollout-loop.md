## 八步集中冷读

- **第 1 步**：`32 × 8 = 256` 可由图核对；slime、RL、权重和颜色都在图上有白话定义。配置数字与训练调用分开，不暗示实测加速。
- **第 2 步**：prompt 是问题文本，8 份副本起初相同，回答尚未生成；普通空 buffer 起点与源码中的旧组 buffer 路径在来源说明里分开。
- **第 3 步**：8 份问题经当前 v0 权重变成 8 条记录；`tokens` 包含问题和回答的 token ID，`response_length` 只数回答 token，此步不改权重。
- **第 4 步**：reward 是对照标准答案检查；4 个 1 和 4 个 0 明确标为构造值，1／0 的含义和 DeepScaler 的数学检查均在图上。
- **第 5 步**：均值算式完整列出，逐个 1／0 减去 0.5 后得到 ±0.5；只讲同组均值中心化，原始分仍保留。
- **第 6 步**：std 是分数离散程度，ε 防止除以零；无偏标准差分母 `8 − 1 = 7`，代入后 `0.534522`，再算得约 ±0.9354，四舍五入边界已注明。
- **第 7 步**：控制器把 32 组展开并打包为 256 条记录，对应配置中的 global batch size 256；训练内部仍可分小批次、多次更新权重，图中不展开这些步骤。
- **第 8 步**：训练完成后先等待权重更新，再让 SGLang 用 v1 生成；下一轮写「next 32 groups」，不假定 buffer 中一定是新题，传输机制交给第 7 章。
