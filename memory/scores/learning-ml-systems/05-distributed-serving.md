## 七步集中冷读

- **第 1 步**：三个公开日志时刻可相减复算 21.600474 s、0.847491 s 和 22.447965 s；worker 就绪先于 HTTP 启动，单节点日志不冒充多节点耗时目标。
- **第 2 步**：两节点共用模型和会合地址；`in=http` 与 `in=none` 直接区分客户端入口，node 1 没有 HTTP 入口但 worker 仍运行，私有路径和 IP 均用占位符。
- **第 3 步**：`8 ÷ 2 = 4` 与两排各四个 rank 相互核对；TP 只表示拆分同一模型的计算，r0–r7 是跨节点唯一编号，不是推荐配置。
- **第 4 步**：预检与软件保证分开陈述；每台先等本机 4 个 worker，合计 8 个才组成 TP 组。旧指南的静默退出警告保留版本边界，就绪日志不冒充请求成功。
- **第 5 步**：请求只到 node 0，返回字段与回答文本对应；8 是本章教学上限，不是 Dynamo 默认值，一次回答也不检验质量、速度或并发。
- **第 6 步**：蓝色输入和橙色输出共用同一客户端入口、rank 0 scheduler 和 8 个 TP worker；请求路径依据固定源码，未从操作记录推出性能或内部耗时。
- **第 7 步**：0、250、275、295、325 ms 复用第 1 章构造例，TTFT、3 段 ITL 和 E2E 可复算；4 个 token 不超过上限 8，客户端计时不能拆分内部等待，章末问题指向 slime 循环。
