## 这一章讲清的事

- 听写和文件转写是两条路线：听写从麦克风经听写 session、整理、历史到光标；文件从磁盘经 `Voxt transcribe` 到 SRT 或 TXT。
- 文件路线复用 Transcribe 选定的语音模型，但不打开 session、不做整理、不写历史记录。
- macOS 的 `afconvert -f WAVE -d LEI16@16000 -c 1` 把任意可读音频转成 16 kHz 单声道 16 位 PCM；`8 × 16,000 × 2 = 256,000` 字节，加 44 字节文件头；一小时 `3,600 × 16,000 × 2 = 115,200,000` 字节 = 115.2 MB。
- 命令把一行 JSON（`op`、`bytes`、可选 `lang`）和 PCM 送进应用数据目录的 `transcribe.sock`（权限 0600），边写 PCM 边读回复；请求行上限 4 KiB。
- 切句器每 10 ms 看一小片：安静满 450 ms 结束一句；新一句提前 300 ms 开始；到 7 秒没有停顿时在最后 1 秒最安静的 100 ms 窗口中点切开。
- 350 ms 最短讲话只在停顿结束的 `finalize(end, true)` 路径检查；文件结尾的 `Flush` 不查，剩下多少都交出去。
- 每句送一次模型，按顺序返回；文字为空就丢掉；`--lang` 没给时用听写的语言提示。
- SRT 写编号、起止时间和文字；TXT 每句一行；整段结果最后才落盘，失败不留半个文件。
- 文件路线不写 `store.Entry`、不写 WAV；只在应用日志写长度和句数，不写文字；声音送给本机模型或为 Transcribe 配置的远端服务。
- 章末把问题交给第 11 章：模型文件和应用更新怎样到达这台 Mac。
