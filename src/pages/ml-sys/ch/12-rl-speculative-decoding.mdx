<summary>Where this chapter's claims come from</summary>

This chapter follows `Awesome-ML-SYS-Tutorial/rlhf/slime/spec/readme.md`. Implementation references use `THUDM/slime@1278475ef4757ac8b03b1836dc1dc20fcc2dd56a` and `NVIDIA/Megatron-LM@23e00ed0963c35382dfe8a5a94fb3cda4d21e133`, reproducibility pins chosen for this chapter. Reported experiments and constructed examples are labelled separately.

Step 1 uses the public three-arm experiment at `readme.md:66-94`: MiMo-7B-RL on H200 with DAPO-Math-17k and maximum response length 24k. Frozen speculative decoding reaches 1,464 tokens/s and online draft training reaches 1,667, a 13.9% increase. This is rollout throughput, not an end-to-end RL speedup. The draft–verify mechanism is recalled from Ch. 15 Step 3 rather than retaught.

Step 2 follows `readme.md:25-30` and the pinned `docker/patch/latest/megatron.patch:152-179`. The example sequence is constructed. A hidden state is the target's computed representation at one token position; the training path reuses the target forward's hidden states rather than running another rollout.

Step 3 follows `readme.md:31-46` and `megatron.patch:152-190`. One left shift aligns token `b` with position `a`; the embedding table turns that token ID into model numbers. The MiMo example joins `h(a)` with `e(b)` to train the prediction of `c`, two positions after `a`. This is the desired task, not a claim that an untrained draft already predicts `c`. The stage's dash marks no real token beyond the sequence; the implementation pads with zero.

Step 4 follows `readme.md:46-60` and `megatron.patch:581-603`. Rolling the shifted tokens again produces labels `[c,d,e,0,0]` in the implementation; the stage uses dashes for those absent positions. Cross entropy compares the draft's token scores with the labels. The documented recipe uses `--mtp-loss-scaling-factor 0.2`; this is an auxiliary loss, not a second RL objective for the target.

Further reading: [zero-to-sglang Part II Chapter 10: Speculative Decoding](https://zero-to-sglang.datawhale.cc/eng/part2/Chapter10_Speculative-Decoding.html) and its [code walkthrough](https://zero-to-sglang.datawhale.cc/eng/part2/Chapter10_Speculative-Decoding_code.html).

<summary>本章说法的出处</summary>

本章依据 `Awesome-ML-SYS-Tutorial/rlhf/slime/spec/readme.md`。实现引用固定到 `THUDM/slime@1278475ef4757ac8b03b1836dc1dc20fcc2dd56a` 和 `NVIDIA/Megatron-LM@23e00ed0963c35382dfe8a5a94fb3cda4d21e133`，这是本章选择的可复现版本。公开实验与构造算例分别标明。

第 1 步依据 `readme.md:66-94` 的三组公开实验：MiMo-7B-RL、H200、DAPO-Math-17k，最长回答 24k。冻结 draft 的 rollout 吞吐为 1464 token/s，在线训练 draft 为 1667，提升 13.9%。这里只比较 rollout 吞吐，不声称端到端 RL 加速。draft–verify 机制只回指第 1 本第 15 章第 3 步，不重复讲。

第 2 步依据 `readme.md:25-30` 和固定版本 `docker/patch/latest/megatron.patch:152-179`。五个 token 是构造示例。hidden state 是 target 在一个 token 位置算出的表示；训练路径复用 target 前向已经算出的 hidden state，不额外做一次 rollout。

第 3 步依据 `readme.md:31-46` 和 `megatron.patch:152-190`。序列左移一次后，token `b` 与位置 `a` 对齐；embedding 表把 token 编号变成模型用的数。MiMo 示例合并 `h(a)` 与 `e(b)`，学习预测 `a` 后两个位置的 `c`。这是训练目标，不表示未训练的 draft 已经能猜出 `c`。图上的横线表示序列结尾后没有真实 token；实现用 0 补齐。

第 4 步依据 `readme.md:46-60` 和 `megatron.patch:581-603`。实现把移位后的 token 再左移一次，得到标签 `[c,d,e,0,0]`；图上用横线表示这些不存在的位置。cross entropy 比较 draft 的 token 分数与标签。公开配置使用 `--mtp-loss-scaling-factor 0.2`；这是辅助损失，不是 target 的第二个 RL 目标。
