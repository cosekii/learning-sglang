<summary>Where this chapter's claims come from</summary>

Step 1 subtracts the three timestamps in the public startup log at `Awesome-ML-SYS-Tutorial/sglang/nvidia-dynamo/dynamo.md:79-83`. It is a single-node example, not a multi-node measurement or a startup-time target. The logged sequence agrees with the fixed Dynamo source: `SgLangWorker::start` waits for worker readiness before the HTTP input runs (`lib/llm/src/engines/sglang/worker.rs:341-343`; `launch/dynamo-run/src/lib.rs:407-410`, commit `670661f6fa85f6ffc77433d21b363285d6cec32f`).

Step 2 follows the two public multi-node commands at `dynamo.md:97-106`, replacing their local model path and IP with placeholders. `in=http` runs the HTTP input, while `in=none` leaves the engine running without another user input (`launch/dynamo-run/src/lib.rs:407-443`). Nonzero node ranks are also forced to `Input::None` at lines 246-250. The shared node settings pass into SGLang through `lib/llm/src/engines/sglang/subprocess.rs:59-65` and `sglang_inc.py:43-48`.

Step 3 derives four workers per node from the public `--tensor-parallel-size 8` and `--num-nodes 2`. The fixed `worker.rs:305-324` computes `tp_size_per_node`, assigns contiguous global TP ranks to each node and starts one subprocess per rank. This describes the example's eight-worker configuration, not a recommended size for other models or machines.

Step 4 separates a recommended preflight from guarantees made by the software. The model and shared-address checks come from the public config; compatible-version and process/log checks follow zero-to-sglang's deployment recipe. The fixed source starts the whole TP group together and waits for each node's local ready notifications. The old guide warns at `dynamo.md:130-132` that an SGLang initialization failure may make `dynamo-run` exit silently; this chapter does not generalize that warning to every Dynamo version.

Step 5 adapts the public chat request at `dynamo.md:85-95` into a capped connectivity check. Its eight-token cap is a teaching choice, not a Dynamo default or a result from the public response. The response-field check and the warning about quality and concurrency follow zero-to-sglang's deployment recipe. The fixed HTTP source enables chat completions and connects the request pipeline at `launch/dynamo-run/src/input/http.rs:43-47,95-108`.

Step 6 follows the fixed request pipeline rather than inferring an architecture from the guide's performance claim. `launch/dynamo-run/src/input/http.rs:85-104` links preprocessing, the backend and engine. `worker.rs:425-443,588-758` sends token IDs to rank 0's scheduler and returns scheduler output to the response path. Nonzero nodes receive work from the leader through PyTorch distributed (`launch/dynamo-run/src/lib.rs:235-250`). The figure deliberately omits serialization, socket buffering and HTTP chunking.

The command and log examples describe an old guide. This chapter keeps their version boundary and replaces machine-specific paths and addresses with placeholders rather than presenting them as reusable defaults.

<summary>本章说法的出处</summary>

第 1 步对 `Awesome-ML-SYS-Tutorial/sglang/nvidia-dynamo/dynamo.md:79-83` 的三条公开启动日志做时间相减。它是单节点例子，不是多节点实测，也不是启动耗时目标。固定版本 Dynamo 源码的顺序与日志一致：`SgLangWorker::start` 先等 worker 就绪，再运行 HTTP 输入（`lib/llm/src/engines/sglang/worker.rs:341-343`；`launch/dynamo-run/src/lib.rs:407-410`，提交 `670661f6fa85f6ffc77433d21b363285d6cec32f`）。

第 2 步依据 `dynamo.md:97-106` 的两条公开多节点命令，把本机模型路径和 IP 换成占位符。`in=http` 运行 HTTP 输入，`in=none` 让引擎继续运行而不再开用户输入（`launch/dynamo-run/src/lib.rs:407-443`）。第 246–250 行还会把非 0 节点强制设为 `Input::None`。共同节点设置经 `lib/llm/src/engines/sglang/subprocess.rs:59-65` 和 `sglang_inc.py:43-48` 传给 SGLang。

第 3 步用公开的 `--tensor-parallel-size 8` 和 `--num-nodes 2` 推出每节点 4 个 worker。固定版本 `worker.rs:305-324` 计算 `tp_size_per_node`，给每个节点分配连续的全局 TP rank，并为每个 rank 启动一个子进程。这里只描述示例的 8-worker 配置，不把它推荐给其他模型或机器。

第 4 步把建议的 preflight 与软件保证分开。模型和共同地址检查来自公开配置；版本兼容、进程与日志检查沿用 zero-to-sglang 的部署顺序。固定源码要求整组 TP worker 一起启动，并等待每个节点的本机 ready 通知。旧指南在 `dynamo.md:130-132` 提醒 SGLang 初始化失败可能让 `dynamo-run` 静默退出；本章不把这条限制推广到所有 Dynamo 版本。

第 5 步把 `dynamo.md:85-95` 的公开对话请求改成限制长度的连通性检查。8 个 token 的上限是教学选择，不是 Dynamo 默认值，也不是公开回答的实测结果。回答字段检查，以及不能把一次成功当成质量和并发结论的边界，沿用 zero-to-sglang 的部署顺序。固定 HTTP 源码在 `launch/dynamo-run/src/input/http.rs:43-47,95-108` 开启 chat completions 并连接请求管线。

第 6 步沿固定版本的请求管线画图，不从指南的性能描述反推架构。`launch/dynamo-run/src/input/http.rs:85-104` 串联 preprocessor、backend 和 engine；`worker.rs:425-443,588-758` 把 token ID 交给 rank 0 的 scheduler，再把 scheduler 输出送回响应路径。非 0 节点通过 leader 的 PyTorch distributed 路径接收工作（`launch/dynamo-run/src/lib.rs:235-250`）。图里故意不展开序列化、socket 缓冲和 HTTP 分块。

这些命令和日志来自旧版操作记录。本章保留版本边界，把机器相关路径和地址换成占位符，不把它们写成可照搬的默认值。
