<details class="i18n-en">
<summary>Where this chapter's claims come from</summary>

Step 1 reads `textio.focus` and `PasteCheck.targetReached`. `focus()` returns the focused element's own process PID, not always the app in front; its comment says the element's process is not always the frontmost app. `deliver` pastes into that process. `targetReached` accepts a target that is either the app in front or the owner of the focused element, which covers a non-activating panel. The start app, `Request.Target`, is the app in front when the shortcut was pressed. It still matters in three ways: its element gets the benefit of the doubt, a selection is replaced only there, and its auto key is pressed only there.

Step 2 reads `Secure()` and the `check()` order. `Secure(f)` is true when the focused element's subrole is `AXSecureTextField`. In `check()` the secure test comes before the editable tests, so a password field stops the insert and the paste is not sent. The exit depends on the feature: `session/deliver_test.go` `TestCardSwitch` shows the card opening only when that feature's card is on; with it off, `session_link.go:375-379` copies the result and shows "Not inserted. Copied: press ⌘V to paste."

Step 3 reads `Writable()` and the rest of `check()`. In the start app, an element counts as writable when it is editable, when Accessibility gave an error, or when its role is not one of the non-text roles (a button, list, table and similar). `Editable` is tested first, so an element Accessibility marks editable passes even with a button role. A web area's role, `AXWebArea`, is not in that table, so a web area passes in the start app. In another app, the element must report `Editable`; an unknown element or a page being read there is not enough. A selection replace and VoxtNew's own window also require `Editable`. The card's Insert is the exception: `AnyEditable` skips the start-app `Writable` check, so a user-chosen button can receive the paste (`deliver_test.go:68`); it does not skip the password check.

Step 4 reads `deliver.go` `DefaultVerifyMS` and `PasteCheck.compare`. `DefaultVerifyMS` is 1000 ms. The helper reads the focused element before ⌘V and after it. `compare` reports changed when the value length, value digest, selection or text marker differs; it reports unreadable when nothing could be compared. In `TextIO.swift`, an unchanged result for an `AXWebArea` or an editable web region is changed to `unknown` before it returns. In `insert()`, a plain unchanged result on an ordinary readable field means `ReasonUnconfirmed`, or `ReasonSecureInput` when another app had secure event input on. An `AXWebArea` container with no secure input, and an unknown result, are trusted as inserted; `deliver_test.go` tests an unchanged readable web area as inserted.

Step 5 reads `helper/Sources/VoxtNewHelper/TextIO.swift`. The paste snapshots the general pasteboard unless `KeepClipboard` is set, writes the text, posts ⌘V, and reads the field while `VerifyMS` allows. The old clipboard returns 150 ms after a confirmed insert, or after `RestoreDelayMS` (default 500) when the outcome is unknown. Before restoring it checks `changeCount`; if another program wrote meanwhile, it does not overwrite that write. An unconfirmed posted paste keeps the text on the clipboard, and the session opens the answer card, which offers Insert and Copy. A password or not-editable check returns before the clipboard is written, so it leaves the clipboard alone; `KeepClipboard` is the separate switch that keeps the text there on purpose.

Source revision: `sglang-omni origin/main@3a31bd72e034db37ce5115a03dd4827b449683be`. The deep dive lists the exact files and lines.

<details class="i18n-zh">
<summary>本章说法的出处</summary>

第 1 步读 `textio.focus` 和 `PasteCheck.targetReached`。`focus()` 返回焦点元素自己进程的 PID，不一定是前面的 app；它的注释就写着元素所属进程不一定是前台 app。`deliver` 往那个进程贴。`targetReached` 接受「在前面的 app」或「拥有焦点的 app」，所以非激活浮窗也能收到。start app 是 `Request.Target`，也就是按快捷键那一刻在前面的 app。它仍有三处作用：它的元素读不出时按可信处理，只有它里面的选区会被替换，只有它里面的自动按键会被按下。

第 2 步读 `Secure()` 和 `check()` 的顺序。焦点元素的 subrole 是 `AXSecureTextField` 时，`Secure(f)` 为真。`check()` 里密码框检查排在可编辑检查前面，所以密码框会终止投递，不发粘贴。出口看功能设置：`session/deliver_test.go` 的 `TestCardSwitch` 证明只有该功能卡片开着才打开答案卡；关着时 `session_link.go:375-379` 复制结果并显示「Not inserted. Copied: press ⌘V to paste.」。

第 3 步读 `Writable()` 和 `check()` 余下部分。在 start app 里，元素可编辑、Accessibility 报错、或它的角色不在非文字角色表（按钮、列表、表格等）里，都算能写。`Editable` 先判断，所以 Accessibility 说可编辑的按钮也能通过。网页区域的角色 `AXWebArea` 不在这张表里，所以 start app 里网页区域也通过。在别的 app 里，元素必须报 `Editable`，读不出或正在阅读的网页都不算够。卡片的 Insert 是例外：`AnyEditable` 跳过 start app 的 `Writable` 检查，用户选中的按钮也能收到粘贴（`deliver_test.go:68`）；它不跳过密码框检查。替换选区和 VoxtNew 自己的窗口也要求 `Editable`。

第 4 步读 `deliver.go` 的 `DefaultVerifyMS` 和 `PasteCheck.compare`。`DefaultVerifyMS` 是 1000 ms。helper 在 ⌘V 之前和之后各读一次焦点。值的长度、值的摘要、选区或文本标记有一项不同，`compare` 就报 changed；什么都比不了就报 unreadable。`TextIO.swift` 会把 `AXWebArea` 或可编辑网页区域的「一样」结果先改成 `unknown`。在 `insert()` 里，普通可读框的 `CheckUnchanged` 变成 `ReasonUnconfirmed`；如果别的 app 开着 secure event input，就变成 `ReasonSecureInput`。没有 secure input 的 `AXWebArea` 容器，以及 `unknown` 结果，都按已贴入处理；`deliver_test.go` 就测了读得出但没变的网页区域按已贴入处理。

第 5 步读 `helper/Sources/VoxtNewHelper/TextIO.swift`。粘贴在没设 `KeepClipboard` 时先给系统剪贴板拍快照，写入文字，发 ⌘V，并在 `VerifyMS` 允许的时间内读焦点。确认贴入后 150 ms 放回旧剪贴板；结果不确定时按 `RestoreDelayMS`（默认 500）放回。放回前先看 `changeCount`；这中间别的程序写过，就不覆盖那次写入。发出粘贴但没确认时，文字留在剪贴板，session 打开答案卡，提供 Insert 和 Copy。密码框和不可编辑的检查在写剪贴板之前返回，不动剪贴板；`KeepClipboard` 是另一个开关，故意把文字留下。

本章源码版本：`sglang-omni origin/main@3a31bd72e034db37ce5115a03dd4827b449683be`。精确文件和行号见深入讲解。
