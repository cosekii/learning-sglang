<summary>Where this chapter's claims come from</summary>

Step 1 reads one history entry. `store.Entry` holds the kind, created time, status, app, the recognised and delivered texts, and the recording's file name in `Audio` (`Voxt/internal/store/store.go:69`). `session/run.go`'s `keep()` writes that entry and, when `KeepAudio` is on or the recognition failed, writes the WAV and sets `Audio` (`run.go:506`, `run.go:546-551`). History is kept only when `privacy.keepHistory` is on, which is its default.

Step 2 reads the two defaults: `settings.History` keeps entries for `DefaultKeepDays = 90` days and keeps any count (`Voxt/internal/settings/history.go:28`, `history.go:35`); a recording kept for a retry lasts `DefaultAudioRetention = 7 * 24 * time.Hour` (`Voxt/internal/session/session.go:355`). The row clock starts at the shortcut: `keep()` stores `CreatedAt: s.StartedAt` (`run.go:512`), and `StartedAt` is the shortcut time (`session.go:169`). The retry recording clock starts when `keep()` writes the WAV and sets `AudioUntil` (`run.go:550-554`), before `History.Put` writes the row (`run.go:561-564`). The second clock exists only when recognition failed or the user cancelled and `KeepAudio` is off (`run.go:583`).

Step 3 reads the age cut: `History.Cutoff` is `now.AddDate(0, 0, -Days())` (`settings/history.go:61`), and `pruneWhere` deletes rows with `created_at < cutoff` (`Voxt/internal/store/sqlitestore/history_retention.go:123`). The clean-up runs at start, after each history change and when the setting changes (`Voxt/history_settings_ops.go:7`).

Step 4 reads the count cut: `retention()` builds `store.Retention{Before: h.Cutoff(now), PerKind: h.PerKind()}` (`history_settings_ops.go:43-44`), and `pruneWhere` tests `rt.PerKind > 0` and deletes each kind's rows past the newest N using `ROW_NUMBER() OVER (PARTITION BY kind …)` (`history_retention.go:125`, `history_retention.go:129`). The choices are 0 (no limit), 50, 100, 300, 500 and 1000 (`settings/history.go:35`).

Step 5 reads the retry clock: when a recording is kept only for a retry, `AudioUntil = now + Config.AudioRetention` (`run.go:552`). `expireRecordings` starts at app launch and calls `History.ExpireAudio` every `recordingSweep = time.Hour` (`Voxt/history_retry.go:89`, `history_retry.go:91`). `ExpireAudio` clears `audio` and `audio_until` only where the row still names the same file (`history.go`); the expiry time is a threshold, and the file goes at the first hourly sweep after it while the app runs (`history_retry.go:91-107`). A successful retry removes a retry-only recording at once (`Voxt/internal/session/retry.go:82`).

Step 6 reads `Manager.Retry`: it reads the WAV, rejects a missing recording or a file that is not 16 kHz mono (`retry.go:52`, `retry.go:60`), recognises the whole file (`retry.go:157`, `retry.go:175`), runs the feature's language-model step with the current settings when the feature has one, and writes the same entry back (`retry.go:93`). A Transcribe retry can return before the language model after a whole-text snippet, when cleanup is off, or when no LLM is available (`retry.go:196-204`); Translate and Rewrite need one. It inserts nothing; its comment says so (`retry.go:38-39`).

Step 7 reads the JSONL export. `historyapi.Row` is the schema; the struct starts at `Voxt/internal/historyapi/row.go:22`. `app`, `instruction`, `target_lang`, `selection` and `typed` carry `omitempty` (`row.go:26`, `row.go:29-32`), so a Transcribe row with an unknown app has no `app` key, and a Transcribe row has neither `instruction` nor `target_lang`. JSONL encodes the whole row (`render.go:38-42`). `Walk` filters to finished entries, oldest first (`row.go:56`). `selection` needs include selected text on; `typed` needs that setting, a Rewrite, and spoken words (`row.go:44-49`). `--day`, `--since`, `--until`, `--kind` and `--format jsonl` are described in `Voxt/docs/history-access.md`.

Step 8 reads the Markdown export. The renderer groups by the row's local day and writes `- HH:MM · App: text` (`render.go:47-65`). Only `created_at` (as the day heading and `HH:MM`), `app` (when known) and `text` appear; `id`, `kind`, `heard`, `instruction`, `target_lang`, `selection` and `typed` are absent. Neither format writes recordings, web addresses, errors, internal names or timings.

Step 9 reads `history_access_controller.go`: the socket is opened only while `privacy.historyAccess` is on (`history_access_controller.go:78`, `syncHistoryAccess`); the read log and the new-program notice are written by the audit hook for valid export/status requests; malformed or unsupported requests return before it (`server.go:151-159`). `historyapi.Listen` sets mode `0600` (`Voxt/internal/historyapi/server.go:101`, the chmod at `server.go:111`), the audit record is `Read` (`server.go:63-70`) written by the call at `server.go:167-169`, and the docs say the switch is not a boundary against programs running as the same user (`Voxt/docs/history-access.md`).

<summary>本章说法的出处</summary>

第 1 步读一条历史记录。`store.Entry` 装着功能种类、创建时间、状态、应用、识别和交付的文字，以及 `Audio` 里的录音文件名（`Voxt/internal/store/store.go:69`）。`session/run.go` 的 `keep()` 写这条记录；当 `KeepAudio` 开着或识别失败时，它写出 WAV 并设置 `Audio`（`run.go:506`、`run.go:546-551`）。只有 `privacy.keepHistory` 开着才写历史，这是默认值。

第 2 步读两个默认值：`settings.History` 默认留 `DefaultKeepDays = 90` 天，条数不限（`Voxt/internal/settings/history.go:28`、`history.go:35`）；为重试留的录音保留 `DefaultAudioRetention = 7 * 24 * time.Hour`（`Voxt/internal/session/session.go:355`）。记录钟从按下快捷键开始：`keep()` 保存 `CreatedAt: s.StartedAt`（`run.go:512`），`StartedAt` 就是快捷键时间（`session.go:169`）。重试录音的钟从 `keep()` 写出 WAV 并设置 `AudioUntil` 时开始（`run.go:550-554`），早于 `History.Put` 写记录（`run.go:561-564`）。第二个钟只在识别失败或用户取消、并且 `KeepAudio` 关着时存在（`run.go:583`）。

第 3 步读按年龄的分界：`History.Cutoff` 是 `now.AddDate(0, 0, -Days())`（`settings/history.go:61`）；`pruneWhere` 删掉 `created_at < cutoff` 的记录（`Voxt/internal/store/sqlitestore/history_retention.go:123`）。清理在启动时、每次历史变化后、设置改动时跑（`Voxt/history_settings_ops.go:7`）。

第 4 步读按条数的分界：`retention()` 组装 `store.Retention{Before: h.Cutoff(now), PerKind: h.PerKind()}`（`history_settings_ops.go:43-44`），`pruneWhere` 判断 `rt.PerKind > 0`，再用 `ROW_NUMBER() OVER (PARTITION BY kind …)` 删掉每种功能最新 N 条之外的行（`history_retention.go:125`、`history_retention.go:129`）。选项是 0（不限）、50、100、300、500、1000（`settings/history.go:35`）。

第 5 步读重试录音的钟：只为重试保留录音时，`AudioUntil = now + Config.AudioRetention`（`run.go:552`）。`expireRecordings` 在应用启动时开始，每隔 `recordingSweep = time.Hour` 调一次 `History.ExpireAudio`（`Voxt/history_retry.go:89`、`history_retry.go:91`）。`ExpireAudio` 只在行里仍是同一个文件名时清掉 `audio` 和 `audio_until`（`history.go`）；到期时间是门槛，应用运行时到点后的第一次每小时清扫才删文件（`history_retry.go:91-107`）。重试成功会立刻删掉只为重试保留的录音（`Voxt/internal/session/retry.go:82`）。

第 6 步读 `Manager.Retry`：它读 WAV，缺录音或不是 16 kHz 单声道就拒绝（`retry.go:52`、`retry.go:60`），把整份文件重新识别（`retry.go:157`、`retry.go:175`），有语言模型时用现在的设置跑该功能对应的那一步，再把同一条记录写回（`retry.go:93`）。听写重试可能停在整段快捷短语、清理关着或没有语言模型时（`retry.go:196-204`）；翻译和改写需要语言模型。它不插入文字；源码注释写明了这一点（`retry.go:38-39`）。

第 7 步读 JSONL 导出。`historyapi.Row` 是结构定义；结构体从 `Voxt/internal/historyapi/row.go:22` 开始。`app`、`instruction`、`target_lang`、`selection`、`typed` 带 `omitempty`（`row.go:26`、`row.go:29-32`），所以应用未知的听写没有 `app` 键，听写也没有 `instruction` 和 `target_lang`。JSONL 编码整行（`render.go:38-42`）。`Walk` 只取完成的记录，从旧到新（`row.go:56`）。`selection` 要打开「包含选中文字」；`typed` 还要同时是带口述的改写（`row.go:44-49`）。`--day`、`--since`、`--until`、`--kind`、`--format jsonl` 的行为写在 `Voxt/docs/history-access.md`。

第 8 步读 Markdown 导出。渲染器按记录的本地日期分组，写 `- HH:MM · App: text`（`render.go:47-65`）。只出现 `created_at`（作为日标题和 `HH:MM`）、`app`（知道时）和 `text`；`id`、`kind`、`heard`、`instruction`、`target_lang`、`selection`、`typed` 不出现。两种格式都不写录音、网址、错误、内部名字和计时。

第 9 步读 `history_access_controller.go`：只有 `privacy.historyAccess` 开着时才开 socket（`history_access_controller.go:78`、`syncHistoryAccess`）；读取日志和新程序提醒由审计回调写入，只有合法的 export／status 请求会走到这里；格式错误或不支持的请求在 `server.go:151-159` 就返回。`historyapi.Listen` 把权限设成 `0600`（`Voxt/internal/historyapi/server.go:101`，chmod 在 `server.go:111`）；审计记录是 `Read`（`server.go:63-70`），由 `server.go:167-169` 的调用写入；文档说明这个开关不是针对同一用户下程序的边界（`Voxt/docs/history-access.md`）。
