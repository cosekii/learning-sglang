<summary>Where this chapter's claims come from</summary>

Step 1 reads the term and its parts. A term is `store.Term`: `Term`, `Aliases`, `Note`, `Enabled`, timestamps. `Clean` trims each to one line, drops empty aliases, the term itself and case-insensitive duplicates, and keeps at most `MaxAliases = 10`; `Check` refuses an empty term, a newline, or more than `MaxTermChars = 80` runes (`dict.go`).

Step 2 reads the four destinations and their switches. A row's `store.Term.Note` is private and is not sent anywhere (`internal/store/store.go:215-230`). `SpeechHints` returns `dict.Hints` only when `Dictionary.Enabled && Dictionary.ASRHints` (`session/run_audio.go`). `spoken()` replaces aliases only when `Dictionary.Enabled` (`session/cleanup.go`). `glossary()` copies only `Term` and `Aliases` into `compose.Term`, only when `Dictionary.Enabled && Dictionary.Glossary` (`session/run_transcribe.go:110-120`). The separate dictionary-wide `settings.Dictionary.Notes` goes to `PromptDictionary` only when `Dictionary.Enabled && !NotesOff` (`session/text.go:120-126`).

Step 3 reads `dict.Hints`: it clones the terms, sorts stable by `UpdatedAt` descending, keeps enabled ones once (ignoring case via lower-cased key), and returns each term as one line. Aliases are not included; the doc comment says they are what recognition gets wrong. A downstream service with fewer hint slots drops hints from the end, preserving the newest-first prefix (`dict.go:89-106`).

Step 4 reads `dict.Replace` and `matchText`. Enabled terms' aliases are matched; Latin aliases need word boundaries on both ends (`wordRune`), CJK aliases match anywhere; patterns are sorted longest first; a term already written as itself is kept (it is only added as a pattern when `highlight`). `spoken()` in `session/cleanup.go` calls `dict.Replace(raw, r.terms)` and is called before `transcribe()` in `session/run.go:301,312`.

Step 5 reads `compose.Build`. With at most `GlossaryAllUpTo = 30` distinct terms, all become candidates and the rendered glossary sits in system. With more than 30, only terms or aliases mentioned in the replaced text become candidates; system keeps generic rules and the selected `<glossary>` opens the user message when matches exist (`compose.go:366-377`, `411-416`). In both cases the output is the longest candidate prefix that fits 60 lines and 2000 bytes, stopping at the first over-budget line without truncating it (`compose.go:576-580`). Go's `len(string)` counts UTF-8 bytes; the limit excludes the surrounding tags. The request input is `call Priya.` after alias replacement. An unchanged system prefix may let the provider reuse its prompt cache, with no guaranteed time or token saving (`compose_test.go:574-577`, `595-630`).

Step 6 reads `PromptDictionary` and `addDictionary`: the note is trimmed and added as the `dictionary` layer after the task layers and before scene, glossary and input, so the system-prompt prefix stays stable (`compose/dictionary.go`). It is never passed to ASR or to `dict.Replace`.

Step 7 is a status read: `SpeechHints` and `spoken()`/`dict.Replace` do not call the language model; `Glossary` and `addDictionary` are only used when a cleanup request is built.

Source revision: `sglang-omni origin/main@3a31bd72e034db37ce5115a03dd4827b449683be`. The deep dive lists exact files and lines.

<details class="i18n-zh">
<summary>本章说法的出处</summary>

第 1 步读词条和它的组成部分。一个词条是 `store.Term`：`Term`、`Aliases`、`Note`、`Enabled` 和两个时间。`Clean` 把它压成单行，丢掉空别名、词条本身和仅大小写不同的重复别名，最多留 `MaxAliases = 10` 个；`Check` 拒绝空词条、含换行、或超过 `MaxTermChars = 80` 个字符的词条（`dict.go`）。

第 2 步读四个去处和它们的开关。行内的 `store.Term.Note` 是私有的，不发送到任何地方（`internal/store/store.go:215-230`）。`SpeechHints` 只在 `Dictionary.Enabled && Dictionary.ASRHints` 时返回 `dict.Hints`（`session/run_audio.go`）。`spoken()` 只在 `Dictionary.Enabled` 时替换别名（`session/cleanup.go`）。`glossary()` 只在 `Dictionary.Enabled && Dictionary.Glossary` 时把 `Term` 和 `Aliases` 复制进 `compose.Term`，不复制备注（`session/run_transcribe.go:110-120`）。另一处整部词典的 `settings.Dictionary.Notes` 只在 `Dictionary.Enabled && !NotesOff` 时交给 `PromptDictionary`（`session/text.go:120-126`）。

第 3 步读 `dict.Hints`：复制词条，按 `UpdatedAt` 从新到旧稳定排序，启用的只留一次（用小写键忽略大小写），每条词条压成单行返回。别名不在里面；注释说别名正是识别会写错的东西。下游服务槽位更少时从末尾删，保留列表前面的新词条（`dict.go:89-106`）。

第 4 步读 `dict.Replace` 和 `matchText`。匹配启用词条的别名；拉丁别名两端要单词边界（`wordRune`），中日韩别名任意位置匹配；模式按长度从长到短排序；已经按词条写好的原文保持原样（只在 `highlight` 时把词条本身也当模式）。`session/cleanup.go` 的 `spoken()` 调用 `dict.Replace(raw, r.terms)`，并在 `session/run.go:301,312` 里排在 `transcribe()` 之前。

第 5 步读 `compose.Build`。不超过 `GlossaryAllUpTo = 30` 个不同词条时，全部先成为候选，术语表放在 system。超过 30 个时，只把替换后的文字提到的词条或别名作为候选；system 只留通用规则，有匹配时选中的 `<glossary>` 放在 user 开头（`compose.go:366-377`、`411-416`）。两种情况都取同时满足 60 行和 2000 字节的最长候选前缀，遇到首个超预算的行就停，不截断那一行（`compose.go:576-580`）。Go 的 `len(string)` 计算 UTF-8 字节，上限不含外层标签。这次请求的输入是别名替换后的 `call Priya.`。provider 可能复用未变的 system 前缀，不保证省时或省 token（`compose_test.go:574-577`、`595-630`）。

第 6 步读 `PromptDictionary` 和 `addDictionary`：备注去掉首尾空白，作为 `dictionary` 一层加在任务说明之后、scene／术语表／输入之前，所以 system 提示的前缀保持不变（`compose/dictionary.go`）。它从不去 ASR，也不进 `dict.Replace`。

第 7 步是状态盘点：`SpeechHints` 和 `spoken()`／`dict.Replace` 不调用语言模型；`Glossary` 和 `addDictionary` 只在组装清理请求时用上。

本章源码版本：`sglang-omni origin/main@3a31bd72e034db37ce5115a03dd4827b449683be`。精确文件和行号见深入讲解。
