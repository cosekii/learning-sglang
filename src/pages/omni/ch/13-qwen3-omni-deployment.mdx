<summary>Where this chapter's claims come from</summary>

Step 1 counts the shipped startup shapes. Text-only mode defines six stages in one `pipeline` process on one GPU and still accepts multimodal input (`sglang_omni/models/qwen3_omni/config.py:136-147,257-265,412-422`; `docs/cookbook/qwen3_omni.md:46-57`). Default speech defines seven stages, each in its own process: image encoder, audio encoder, thinker and code2wav use GPU 0, talker uses GPU 1, and preprocessing and decode are CPU stages (`config.py:268-318,425-452`). These counts exclude the HTTP server and coordinator.

Step 2 separates server mode from requested output. Both modes accept multimodal input (`docs/cookbook/qwen3_omni.md:206-208`). Text-only joins active input branches at `mm_aggregate`; the speech thinker merges them itself (`sglang_omni/models/qwen3_omni/config.py:136-189,212-254`). A speech request with `modalities: ["text"]` terminates at decode and excludes talker; adding `"audio"` also terminates at code2wav (`sglang_omni/models/qwen3_omni/request_builders.py:200-261`; `tests/unit_test/qwen3_omni/test_pipeline.py:898-930,1935-1947`). The public default is text output, and a text-only server returns no audio when audio is requested (`docs/basic_usage/omni.md:154-170,199-200,386-395`).

Step 3 uses the public placement experiment from Chapter 8 Step 1. At concurrency eight, moving only the talker from the thinker's GPU to its own reduced mean-of-two p90 first sound from 2.680 to 1.439 seconds, about 46%. Code2wav stayed beside the thinker in both arms. The same guide reports a separate single-stream result: isolation improved first sound but increased end-to-end latency by 14–17%, so the chapter does not turn one metric into a universal rule (`docs/cookbook/qwen3_omni/tuning.md:52-69`).

Step 4 starts with the H100 BF16 colocated YAML's declared `2 + 2 + 78 + 10 + 2 = 94%` (`examples/configs/qwen3_omni_colocated_h100_bf16.yaml:1-20`). The thinker factory defaults `encoder_mem_reserve` to 0.05 and subtracts it before deriving the AR budget when the colocated stage fraction is not matched by an explicit `mem_fraction_static`; the effective AR fraction is therefore `0.78 − 0.05 = 0.73` (`sglang_omni/models/qwen3_omni/stages.py:1230-1243,1358-1373`; `tests/unit_test/qwen3_omni/test_sglang_ar_budget.py:476-488,514-537`). Colocation requires one common GPU, TP 1, no talker/code2wav process replicas and a declared budget for every GPU stage (`sglang_omni/models/qwen3_omni/placement.py:55-60,84-108,122-187`). These are configuration arithmetic and validation rules, not measured occupancy.

Step 5 compares the three precision rows in the compatibility matrix: BF16, native FP8 and AutoRound INT4 all support text-only, disaggregated TP1/TP2 and colocated TP1 (`docs/cookbook/qwen3_omni.md:25-44`). BF16 is the default. Native FP8 reads the checkpoint quantization config for thinker and talker AR; it is not a generic `--dtype fp8` option (`docs/cookbook/qwen3_omni.md:153-169`; `sglang_omni/models/weight_loader.py:19-42`). The AutoRound checkpoint uses 4-bit group-size-128 thinker weights while speech talker and code2wav remain BF16 (`docs/cookbook/qwen3_omni.md:181-195`). The approximately 60, 40 and 30 GB values and their 50%/25% reductions are documentation estimates, not local footprint, latency or quality measurements (`docs/cookbook/qwen3_omni.md:196-200`).

Step 6 applies the shipped replica2 YAML. The thinker defaults to 64 running requests; each talker engine defaults to 32 (`sglang_omni/models/qwen3_omni/stages.py:1276-1286`; `sglang_omni/models/qwen3_omni/config.py:37,454-496`). Two talker replicas make the code2wav factory compute `codec_state_slots = 32 × 2 = 64` so its saved codec state can cover the streams the talkers run (`config.py:468-476`; `tests/unit_test/qwen3_omni/test_colocation_config.py:177-203`). The YAML places talker/code2wav replica 0 on GPU 1 and replica 1 on GPU 2, with `12.3% + 1.4% = 13.7%` declared per replica GPU (`examples/configs/qwen3_omni_speech_replica2.yaml:1-42`). This is configuration capacity, not a throughput measurement or a binding-contract guarantee under a custom replica policy.

Step 7 separates health from performance. Readiness sends a small image, one second of audio and a short instruction, with at most eight new tokens per token-generating stage (`docs/cookbook/qwen3_omni.md:202-204`; `sglang_omni/models/qwen3_omni/config.py:328-366`). Video, large batches and other shapes may still warm later. A comparison first resolves the config, then holds input, sampling, hardware and warmup fixed while changing one deployment choice (`docs/basic_usage/process_topology.md:52-53`; Chapter 8 Steps 6 and 8). The documented sweep `--concurrencies 1,16 --repeats 5 --generate-only` gives ten measured runs per arm; raw repeats, failures and memory stay in the comparison. TTFA and server time stay separate from listener stalls and the Chapter 12 stop/response clocks. The benchmark notes that p99 needs at least 100 measured samples (`benchmarks/README.md:249-288`).

Step 8 constructs one starting plan for eight concurrent spoken requests: default BF16 speech, text and audio output, thinker and code2wav on GPU 0, and talker alone on GPU 1. This applies the public concurrency-eight placement evidence without claiming the plan wins locally. Eight is below the 32-request talker cap, leaving `32 − 8 = 24` unallocated cap slots, so the example does not add a replica before measuring a queue. The evidence row keeps first audio, total time, stalls, failures, memory, output quality and raw repeats; interruption tests also keep the Chapter 12 listener clocks. The closing map revisits configuration and binding (Chapters 1–3), readiness, data and queues (4–6), memory and measurement (7–8), and optimization and model strategies (9–12).

Code references in this chapter pin to `sglang-omni origin/main@9725235249df851281d4dc62a04b2d34b02ac0fe`. The chapter reads source, shipped configs and public measurements; it does not run a model or benchmark.

<summary>本章说法的出处</summary>

第 1 步数随仓库发布的启动形态。纯文字模式把六个 stage 放在一个 `pipeline` 进程和一张 GPU 上，仍接受多模态输入（`sglang_omni/models/qwen3_omni/config.py:136-147,257-265,412-422`；`docs/cookbook/qwen3_omni.md:46-57`）。默认语音有七个 stage，各住一个进程：image encoder、audio encoder、thinker 和 code2wav 使用 GPU 0，talker 使用 GPU 1，preprocessing 和 decode 是 CPU stage（`config.py:268-318,425-452`）。这些数量不含 HTTP server 和 coordinator。

第 2 步区分服务器模式和请求输出。两种模式都接受多模态输入（`docs/cookbook/qwen3_omni.md:206-208`）。纯文字在 `mm_aggregate` 汇合实际输入分支；语音部署由 thinker 自己汇合（`sglang_omni/models/qwen3_omni/config.py:136-189,212-254`）。语音请求使用 `modalities: ["text"]` 时以 decode 为终点并排除 talker；加入 `"audio"` 后也以 code2wav 为终点（`sglang_omni/models/qwen3_omni/request_builders.py:200-261`；`tests/unit_test/qwen3_omni/test_pipeline.py:898-930,1935-1947`）。公开请求默认只输出文字；向纯文字服务器请求声音也不会返回声音（`docs/basic_usage/omni.md:154-170,199-200,386-395`）。

第 3 步使用第 8 章第 1 步的公开摆卡实验。8 路并发时，只把 talker 从 thinker 所在 GPU 移到另一张卡，两次 p90 首音的均值从 2.680 秒降至 1.439 秒，约 46%。两组实验的 code2wav 都留在 thinker 旁边。同一指南另报单请求结果：独占改善首音，却让端到端延迟增加 14–17%，所以本章不把一项指标写成通用规则（`docs/cookbook/qwen3_omni/tuning.md:52-69`）。

第 4 步从 H100 BF16 同卡 YAML 的 `2 + 2 + 78 + 10 + 2 = 94%` 开始（`examples/configs/qwen3_omni_colocated_h100_bf16.yaml:1-20`）。thinker 工厂默认 `encoder_mem_reserve` 为 0.05；当同卡 stage 比例没有匹配显式 `mem_fraction_static` 时，会先减去这份预留再推导 AR 预算，所以有效 AR 比例是 `0.78 − 0.05 = 0.73`（`sglang_omni/models/qwen3_omni/stages.py:1230-1243,1358-1373`；`tests/unit_test/qwen3_omni/test_sglang_ar_budget.py:476-488,514-537`）。同卡要求五个 GPU stage 共用一卡、TP 为 1、talker 和 code2wav 不复制进程，并且每个 GPU stage 都申报预算（`sglang_omni/models/qwen3_omni/placement.py:55-60,84-108,122-187`）。这些是配置算式与校验规则，不是实测占用。

第 5 步对照兼容矩阵的三种精度：BF16、native FP8 和 AutoRound INT4 都支持纯文字、分卡 TP1/TP2 和同卡 TP1（`docs/cookbook/qwen3_omni.md:25-44`）。BF16 是默认值。native FP8 为 thinker 和 talker AR 读取 checkpoint 的量化配置，不是通用的 `--dtype fp8` 选项（`docs/cookbook/qwen3_omni.md:153-169`；`sglang_omni/models/weight_loader.py:19-42`）。AutoRound checkpoint 的 thinker 使用 4 bit、group size 128 权重，语音 talker 和 code2wav 仍是 BF16（`docs/cookbook/qwen3_omni.md:181-195`）。约 60、40、30 GB 及 50%/25% 降幅是文档估计，不是本地显存、延迟或质量实测（`docs/cookbook/qwen3_omni.md:196-200`）。

第 6 步应用随仓库发布的 replica2 YAML。thinker 默认最多运行 64 个请求，每个 talker engine 默认 32 个（`sglang_omni/models/qwen3_omni/stages.py:1276-1286`；`sglang_omni/models/qwen3_omni/config.py:37,454-496`）。两个 talker 副本让 code2wav 工厂计算 `codec_state_slots = 32 × 2 = 64`，用保存的 codec 状态覆盖 talker 可运行的流（`config.py:468-476`；`tests/unit_test/qwen3_omni/test_colocation_config.py:177-203`）。YAML 把 talker/code2wav 副本 0 放在 GPU 1，副本 1 放在 GPU 2，每个副本 GPU 申报 `12.3% + 1.4% = 13.7%`（`examples/configs/qwen3_omni_speech_replica2.yaml:1-42`）。这是配置容量，不是吞吐实测；自定义副本策略下也不是绑定契约保证。

第 7 步区分健康与性能。readiness 发送一张小图、一秒声音和一条短指令，每个生成 token 的 stage 最多生成 8 个新 token（`docs/cookbook/qwen3_omni.md:202-204`；`sglang_omni/models/qwen3_omni/config.py:328-366`）。视频、大 batch 和其他形状可能仍会在之后预热。比较先解析配置，再固定输入、采样、硬件和预热，只改一个部署选择（`docs/basic_usage/process_topology.md:52-53`；第 8 章第 6、8 步）。文档中的 `--concurrencies 1,16 --repeats 5 --generate-only` 给每组十次测量；原始重复、失败和显存也进入比较。TTFA 和服务器时间与听者卡顿、第 12 章停答／回应时钟分开。benchmark 说明 p99 至少需要 100 个测量样本（`benchmarks/README.md:249-288`）。

第 8 步为 8 路并发语音请求构造一个起步方案：默认 BF16 语音、文字和声音输出、thinker 和 code2wav 在 GPU 0、talker 独占 GPU 1。这里应用公开的 8 路摆卡证据，但不声称该方案在本地获胜。8 小于 talker 的 32 请求上限，还剩 `32 − 8 = 24` 个未占上限，所以算例不在测量排队前增加副本。证据行保留首音、总耗时、卡顿、失败、显存、输出质量和原始重复；打断测试还保留第 12 章听者时钟。收尾地图回看配置与绑定（第 1–3 章）、就绪、数据与队列（第 4–6 章）、显存与测量（第 7–8 章）、优化与模型策略（第 9–12 章）。
