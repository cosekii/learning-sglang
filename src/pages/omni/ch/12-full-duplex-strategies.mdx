<summary>Where this chapter's claims come from</summary>

Step 1 uses a constructed 2.5-second reply. The delivery ledger reaches 2.0 seconds and the client reports 1.2 seconds played, leaving 800 ms delivered but unplayed. `DeliveryPacer.sent()` counts audio handed to the client; it does not observe acoustic playback (`sglang_omni/pipeline/session_delivery.py:112-128`). The default `max_output_lead_ms` is 1,000 ms (`sglang_omni/proto/session.py:19-28`), so the constructed 800 ms interval fits within that delivery horizon. Later steps reuse these exact positions.

Step 2 maps alternatives rather than stages in one pipeline. Turn-based and native full-duplex recall Learning SGLang Ch. 21 Steps 1–2. The new streaming-cascade route sends audio through ASR, a chat-completion LLM and sentence-wise TTS (`docs/developer_reference/full_duplex_guide.md:1582-1591,1622-1645`). MiniCPM-o consumes 1,000 ms units and makes model-led listen/speak decisions (`docs/developer_reference/full_duplex_guide.md:391-397`). These are different systems, so the chapter does not treat their measurements as an isolated architecture benchmark.

Step 3 follows the Session graph's turn-named interrupt. It drops matching chunks from the target inbox, unsent appends, the delivery pacer and unread client output, while preserving client input (`sglang_omni/pipeline/session_graph.py:108-173`). A preempting interrupt also names already submitted appends so their owners abort them (`session_graph.py:175-210`). Later output from an interrupted reply remains fenced (`session_graph.py:581-619`; `sglang_omni/pipeline/sessions.py:167-210`). `reply.delivered` reports the connection's delivered duration (`session_graph.py:212-232`; `session_delivery.py:112-128`), not the listener's acoustic position.

Step 4 uses Qwen's `heard_tokens(audio_end_ms) = 3 + floor(audio_end_ms ÷ 80)`. One codec frame is 1,920 samples at 24 kHz, or 80 ms; the talker prefill consumes three text rows before one row per codec frame (`sglang_omni/models/qwen3_omni/thinker_session.py:38-42,87-89`). Thus D maps to 28 rows and H to 18. The generated 2.5-second example has `3 + floor(2,500 ÷ 80) = 34` rows; its 31 complete sound rows cover 2,480 ms and the remaining 20 ms is not a complete row. The thinker keeps the smaller cut in either arrival order (`thinker_session.py:167-223`; `session_input.py:253-260`). If no reply audio was delivered, Qwen instead carries the original utterance into the next unit and asks it again (`session_input.py:184-205`; `tests/unit_test/qwen3_omni/test_session_input.py:102-138`).

Step 5 follows the cascade's default `method: sentence` (`sglang_omni/models/streaming_cascade/alignment.py:98-138`). Its dialog takes the smaller of client H and delivered D, then keeps text through the last progress boundary whose audio ended at or before that cut (`sglang_omni/models/streaming_cascade/dialog.py:66-78,857-903`). In the constructed progress list `(1.0 s, 2.0 s, 2.5 s)`, D retains two sentences and H retains one. The three sentence texts are teaching examples, not model output. An unfinished retained prefix is marked uncertain. If no text remains, the empty assistant entry disappears and adjacent user messages join (`dialog.py:906-917`). ASR alignment can retain a finer verified prefix. ASR failure, timeout or mismatch adds no finer prefix; forced alignment still retains the sentence end and any already reported word ends (`alignment.py:219-229,389-522`).

Step 6 follows MiniCPM-o's client `response.cancel` and `conversation.item.truncate`. Cancel initially keeps through the last adapter-delivered unit. A client truncate then keeps only delivered units whose audio fully ended by H, and later truncates can only move backward (`sglang_omni/models/minicpm_o/session_adapters.py:469-516,553-640`). Thus D=2.0 seconds keeps units 0 and 1, while H=1.2 seconds keeps only unit 0. The `1,200 − 1,000 = 200 ms` heard inside unit 1 has no whole-unit history representation. The thinker drops later spoken units, restores earlier generated history and refills later user input as forced-listen units (`session_adapters.py:118-179,219-236`). This is separate from the model-led decision to stop speaking.

Step 7 uses the duplex profiler's fixed test example: ready→admitted is 150 ms and admitted→first output is 50 ms, so ready→first output is 200 ms (`tests/unit_test/profiler/test_duplex_metrics.py:318-344`). The implementation computes each interval within one Unit before combining results (`sglang_omni/profiler/duplex_metrics.py:150-157,282-337`). Ready means all required input is present; admitted means the coordinator accepts the append. First output is the first model-content chunk entering the coordinator output buffer, potentially text, not client first audio (`docs/developer_reference/profiler.md:144-196`). The profiler has no playback-stop endpoint.

Step 8 uses constructed timestamps under unified FDB v1.0. Stop time is the end of the model-speech segment covering interruption onset S minus S. Response time is the first ASR word start N at or after interruption end R, minus R (`benchmarks/duplex/unified_v10.py:165-174,193-225`). Thus the constructed old-audio stop wait is 4.3−3.0=1.3 seconds and response wait is 5.1−4.0=1.1 seconds. N is an ASR word boundary, not necessarily first audio. If no model speech covers S, the sample is `not_exercised`; if speech covers both S and R, it is `speaking_at_end`, with no response latency. The closing deployment question belongs to Chapter 13.

Code references in this chapter pin to `sglang-omni origin/main@9725235249df851281d4dc62a04b2d34b02ac0fe`. The chapter reads source and tests; it does not run a model or benchmark.

<summary>本章说法的出处</summary>

第 1 步构造一段 2.5 秒回答。交付记录到 2.0 秒，客户端报告播放到 1.2 秒，因此有 800 ms 已交付但未播放。`DeliveryPacer.sent()` 统计交给客户端连接的声音，不观察真实播放（`sglang_omni/pipeline/session_delivery.py:112-128`）。默认 `max_output_lead_ms` 是 1,000 ms（`sglang_omni/proto/session.py:19-28`），所以这段 800 ms 构造间隔在默认交付范围内。后续步骤沿用同一组位置。

第 2 步画的是替代方案，不是同一条流水线的三段。turn-based 和 native full-duplex 回指 Learning SGLang 第 21 章第 1–2 步。新的 streaming cascade 路线把声音依次交给 ASR、聊天补全 LLM 和逐句 TTS（`docs/developer_reference/full_duplex_guide.md:1582-1591,1622-1645`）。MiniCPM-o 每份输入是 1,000 ms，由模型选择听或说（`docs/developer_reference/full_duplex_guide.md:391-397`）。三者是不同系统，本章不把它们的测量差值当成只由架构造成的 benchmark 结果。

第 3 步跟随 Session graph 中指定 turn 的 interrupt。它从目标 inbox、未送出 appends、delivery pacer 和未读客户端输出中删除匹配 chunks，同时保留客户端输入（`sglang_omni/pipeline/session_graph.py:108-173`）。带 preempt 的 interrupt 还会点名已提交 appends，让 owner 中止它们（`session_graph.py:175-210`）。被打断回答之后到达的输出仍会被边界挡住（`session_graph.py:581-619`；`sglang_omni/pipeline/sessions.py:167-210`）。`reply.delivered` 报告连接已交付的时长（`session_graph.py:212-232`；`session_delivery.py:112-128`），不是听者的真实播放位置。

第 4 步使用 Qwen 的 `heard_tokens(audio_end_ms) = 3 + floor(audio_end_ms ÷ 80)`。一个 codec 帧在 24 kHz 下是 1,920 个采样点，即 80 ms；talker prefill 先读三行文字，之后每个 codec 帧读一行（`sglang_omni/models/qwen3_omni/thinker_session.py:38-42,87-89`）。所以 D 对应 28 行，H 对应 18 行。生成的 2.5 秒算例有 `3 + floor(2,500 ÷ 80) = 34` 行；31 行完整声音覆盖 2,480 ms，其余 20 ms 不足一行。无论两个报告谁先到达，thinker 都保留较小切点（`thinker_session.py:167-223`；`session_input.py:253-260`）。如果没有交付任何回答声音，Qwen 会把原来的说话内容带进下一单元，重新提问（`session_input.py:184-205`；`tests/unit_test/qwen3_omni/test_session_input.py:102-138`）。

第 5 步跟随 cascade 默认的 `method: sentence`（`sglang_omni/models/streaming_cascade/alignment.py:98-138`）。dialog 取客户端 H 与交付 D 的较小值，再保留到最后一个声音结束时刻不超过切点的进度边界（`sglang_omni/models/streaming_cascade/dialog.py:66-78,857-903`）。在构造的 `(1.0 秒, 2.0 秒, 2.5 秒)` 进度列表里，D 保留两句，H 保留一句。三段句子文字是教学算例，不是模型输出。保留文字若在不完整句子前停下，会标成不确定。如果没有文字留下，空 assistant 条目会被删除，相邻 user 消息合并（`dialog.py:906-917`）。ASR 对齐可以保留更细且经过核对的前缀。ASR 失败、超时或不匹配不会增加更细前缀；forced 对齐仍保留句子结束位置和已经报告的词结束位置（`alignment.py:219-229,389-522`）。

第 6 步跟随 MiniCPM-o 的客户端 `response.cancel` 和 `conversation.item.truncate`。cancel 先保留到 adapter 最后交付的单元。客户端 truncate 再只保留声音在 H 前已经全部结束的已交付单元，后续 truncate 只能继续往前挪（`sglang_omni/models/minicpm_o/session_adapters.py:469-516,553-640`）。所以 D=2.0 秒保留 unit 0 和 unit 1，H=1.2 秒只保留 unit 0。unit 1 中被听过的 `1,200 − 1,000 = 200 ms` 无法进入整单元历史。thinker 删除之后的 spoken units，恢复之前的生成记录，并把后续用户输入作为强制 listening 单元补回（`session_adapters.py:118-179,219-236`）。这不同于模型自己决定停止说话。

第 7 步使用 duplex profiler 的固定测试算例：就绪到接纳是 150 ms，接纳到首个输出是 50 ms，所以就绪到首个输出是 200 ms（`tests/unit_test/profiler/test_duplex_metrics.py:318-344`）。实现先在每个 Unit 内计算各段间隔，再做汇总（`sglang_omni/profiler/duplex_metrics.py:150-157,282-337`）。就绪表示需要的输入到齐，接纳表示 coordinator 接受 append。首个输出是进入 coordinator 输出缓冲的第一段模型内容，可能是文字，不是客户端首音（`docs/developer_reference/profiler.md:144-196`）。profiler 没有播放停止端点。

第 8 步使用 unified FDB v1.0 的构造时刻。停答时间等于覆盖打断起点 S 的模型语音段结束时刻减 S。回应时间等于不早于打断结束时刻 R 的首个 ASR 词开始时刻 N 减 R（`benchmarks/duplex/unified_v10.py:165-174,193-225`）。所以构造的旧声音停止等待是 4.3−3.0=1.3 秒，回应等待是 5.1−4.0=1.1 秒。N 是 ASR 词边界，不一定是首个声音。如果 S 时没有模型语音，样本是 `not_exercised`；如果 S 和 R 都被模型语音覆盖，样本是 `speaking_at_end`，没有回应延迟。章末部署问题由第 13 章回答。
