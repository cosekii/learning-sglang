<details class="i18n-en">
<summary>Where this chapter's claims come from</summary>

Step 1 uses a constructed ten-second response whose reader has taken four seconds. Qwen3-TTS documents 24 kHz float32 audio at about 96 kB per second, so the six-second backlog is `24,000 × 4 × 6 = 576,000 B`. A finished request releases its generation-capacity slot, but streamed audio can remain in the API process until the client reads it (`docs/cookbook/qwen3_tts/tuning.md:22-26`; `sglang_omni/pipeline/coordinator.py:103-109,213-223`). Socket buffering is deliberately excluded from this teaching arithmetic.

Code references in this chapter pin to `sglang-omni origin/main@9725235249df851281d4dc62a04b2d34b02ac0fe`. The chapter reads source and unit tests; it does not run a model or measure a server.
