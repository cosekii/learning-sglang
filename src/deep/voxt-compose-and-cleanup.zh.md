## 第 1 步 · 识别之后选择任务

> **一句话：** 识别结果可以进入整理听写、翻译或改写，改写时口述内容是指令，不是等待改写的结果。

### 图上是什么

- 蓝卡表示第 4 章第 7 步交出的一份识别结果。每次运行从三条任务路线中选一条，不会同时执行三条。
- `Transcribe` 路线把 “Good morning.” 这类识别文字当作要整理的内容。本章用「整理听写」说明这条路线的工作。
- `Translate` 路线把识别文字当作要翻译的内容。
- `Rewrite` 路线把 “Make it shorter.” 这类口述当作指令。要改写的正文可以来自选区或框内输入；从零写作时没有这份正文。
- 三条路线需要不同的任务说明和输入安排，因此不能把同一份固定文字不加区分地发给模型。

### 公式

$$
C=R\times T
$$

| 符号 | 是什么 | 从哪来 |
|---|---|---|
| $C$ | 一次识别结果面临的路线选择数 | 本步计算 |
| $R$ | 一次识别交出的结果数 | 第 4 章第 7 步，1 份 |
| $T$ | 本步列出的任务路线数 | `Transcribe`、`Translate`、`Rewrite`，共 3 条 |

### 代入图上的数

| 要算的量 | 算式 | 结果 |
|---|---|---:|
| 候选任务路线 | $1\times3$ | 3 条 |

这里数的是候选路线。每次运行只选其中一条；三条路线使用不同的构造输入来说明文字在任务里的角色。

### 输入边界

`Transcribe` 和语音 `Translate` 都接收识别文字。`Rewrite` 的口述是指令，后面还可接选区文字和框内输入。词典别名替换发生在任务路由前；历史仍保存识别原文。这个细节不改变本步的三条路线，留给词典章展开。

## 第 2 步 · 固定说明与本次输入分开

> **一句话：** 请求按 `system → history → user` 排列消息，固定说明留在 `system`，本次输入留在 `user`。

### 图上是什么

- `system` 是带给模型的固定说明，包含角色、任务和输出约定；使用清理时，还包含相应规则。它在多次运行之间保持稳定。
- 虚线 `history` 是可选的历史消息，可以放示例或前几轮对话。没有需要的请求不添加这一段。
- 蓝色 `user` 是本次输入，可能装识别文字、选区、框内输入或改写指令。不同任务选择不同字段。
- 三类内容按顺序组成消息列表，再交给第 5 章的请求路线。这里的「稳定」指内容不因本次识别文字而改变，不是延迟或缓存测量。

### 为什么不把输入塞进固定说明

`compose.Build` 先确定任务和模板，再分别构造 system 前缀、可选历史和 user 消息。这样，新一次听写只替换该次输入，不需要重写角色和任务说明。

小词典说明可以留在稳定的 system 前缀。不同词条数超过公开阈值时，只把命中的词条放到 user 开头的 `<glossary>` 块，避免每次识别都改变 system。阈值和词典替换规则不在主图展开。

### 用户文本的包裹边界

Voxt 用 XML 形状的标签包住输入，例如 `<input>…</input>`。如果用户文字本身出现同名闭合标签，组装器会将它转义，使用户文字不能原样关闭自己的包裹。这里的标签是 prompt 约定，不是把输入当成可执行代码。

## 第 3 步 · 五部分组成整理请求

> **一句话：** 整理听写 prompt 可以简化看成四层 system 说明和一份 user 输入，合起来是五个功能部分。

### 图上是什么

- `ROLE` 告诉模型以什么角色完成工作。
- `CLEANUP` 说明要处理哪些口头填充、重复和识别痕迹；它不是对文本执行固定替换的程序。
- `TASK` 指明这次要整理一段听写。
- `OUTPUT` 要求模型把结果放进 `<output>`，让后面的清理程序知道该取哪一段。
- 蓝色 `USER` 用 `<input>` 包住本次识别文字 “Good morning.”。输入值是构造示例。
- 本图按功能省略输入格式、`structure` 或 `form`、示例、词典和场景等层，不把五个部分当成源码 `Layers` 的完整列表。

### 公式

$$
L=I+U
$$

| 符号 | 是什么 | 从哪来 |
|---|---|---|
| $L$ | 本图列出的 prompt 功能部分数 | 本步计算 |
| $I$ | system 中的说明层数 | 角色、清理、任务、输出约定，共 4 层 |
| $U$ | user 中的本次输入份数 | 1 份构造的识别文字 |

### 代入图上的数

| 要算的量 | 算式 | 结果 |
|---|---|---:|
| 本图的 prompt 部分 | $4+1$ | 5 个 |

这是教学图的计数，不是 token 数、字节数或请求条数。五部分仍属于同一次模型请求。

### 完整组装还有哪些层

公开 `Layers` 会按配置加入输入格式、可选 `before`、基本清理、`structure` 或 `form`、任务、共享词典和输出约定。开启清理时，示例追加在 system prompt 内部，不会为了示例增加一轮 history。

如果 `TaskPrompt` 非空，Voxt 进入完整自定义 prompt 分支。它不是把一句话附到内置角色和输出约定后面；保留下来的清理由自定义分支明确处理。
