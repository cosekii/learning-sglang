## 第 1 步 · 识别听错的那个词

> **一句话：** 识别把 Priya 写成 Preeya，词典用一行把「你要的词条」和「识别常写成的别名」配起来。

### 图上是什么

- 左边灰色框是**你的声音**，说着 “call Priya”。
- 中间的**语音模型**（speech model）把声音变成文字，橙色框是它写出来的识别文字 `call Preeya.`。
- 下面说你要的是 `call Priya.`，并指出这个名字每次都得手动改。
- 底部蓝色框是词典的一行：词条 `Priya`、别名 `Preeya`、备注「在设计团队里」。

### 三个部分各是什么

| 部分 | 含义 | 例子 |
|---|---|---|
| 词条（term） | 你希望写出来的正确写法 | `Priya` |
| 别名（alias） | 识别常写成的样子；一个词条可以有多个 | `Preeya` |
| 备注（note） | 你写一次的自由文字，可选 | 在设计团队里 |

`store.Term` 还有 `Enabled` 和两个时间戳；管理员用它决定这个词条此刻是否生效（`Voxt/internal/dict/dict.go`）。`Check` 拒绝空词条、带换行的词条、以及超过 `MaxTermChars = 80` 个字符的词条（`dict.go:70`）；`Clean` 最多保留 `MaxAliases = 10` 个别名（`dict.go:50`）。

### 为什么先讲代价

不认识这个产品名时，识别每次都会写错，你每次都得手改。词典让这件事只做一次：填一行，之后每次听写都用。第 2 步把它拆成四个去处。

### 接下来

一行里有三样东西，它们不会一起走；下一步看每一部分分别去哪里。

## 第 2 步 · 一行有四个去处

> **一句话：** 词条去语音模型当提示，别名去文字稿做替换，词条和别名一起进语言模型术语表；行内备注不发送，整部词典的 `settings.Dictionary.Notes` 才进语言模型提示。

### 图上是什么

- 左边蓝色框是那行词典：词条、别名、行内备注。行内备注标为私有，不发送。
- 右边四个框是四个去处，每个框写着需要哪些开关。第四个来自另一处设置 `settings.Dictionary.Notes`。
- 三条细线从左边词条和别名指向前三个框；行内备注没有箭头。

### 四个去处和开关

| 去处 | 拿到什么 | 开关 | 出处 |
|---|---|---|---|
| 语音模型 · 提示 | 只要启用的词条 | 词典开 + 语音提示开 | `session/run_audio.go:36` |
| 文字稿 · 替换 | 别名换回词条 | 词典开 | `session/cleanup.go:69` |
| 语言模型 · 术语表 | 只复制词条 + 别名，不复制行内备注 | 词典开 + 术语表开 | `session/run_transcribe.go:110-120` |
| 语言模型 · 全词典备注 | 另一处 `settings.Dictionary.Notes` | 词典开，且未关备注 | `session/text.go:120-126` |

行内的 `store.Term.Note` 在源码里明确标为「不发送到任何地方」（`internal/store/store.go:215-230`）。`glossary()` 只新建含 `Term` 和 `Aliases` 的 `compose.Term`，所以行内备注也不会搭术语表进入提示。

开关都在 `settings.Dictionary` 里：`Enabled`、`ASRHints`、`Glossary`、`NotesOff`（`Voxt/internal/settings/settings.go:285-306`）。默认 `Enabled`、`ASRHints`、`Glossary` 都开（`settings.go:393`）。

### 为什么分开

这四个地方吃的东西不一样。识别器只认词表；文字替换只认别名；术语表只复制词条和别名；全词典备注来自另一处设置。行内备注不属于任何一条发送路线。

### 接下来

后四步按这张图一个一个走，每步标出「第几个 / 共 4 个」。

## 第 3 步 · 词条去语音模型当提示

> **一句话：** 启用的词条按「最近改过优先」排好，作为提示交给语音模型；别名不进去。

### 图上是什么

- 左边蓝色框列出两个启用的词条：`Priya` 和 `MOSS-Transcribe`。
- 箭头指向右边的语音模型，框里同样列出这两个词。
- 下方橙色框 `Preeya ✗` 说明别名不发。
- 底部一行说槽位更少的服务从末尾删，保留列表前面的新词条。

### 提示怎么排

`dict.Hints` 复制词条列表，按 `UpdatedAt` 从新到旧稳定排序（`Voxt/internal/dict/dict.go:95`）。然后按顺序收启用的、非空的、忽略大小写不重复的词条（`dict.go:100-103`）。所以图上 2 个词条进、2 条提示出。

$$\text{提示} = [\text{启用的词条，按 } UpdatedAt \text{ 从新到旧}]$$

| 符号 | 是什么 | 从哪来 |
|---|---|---|
| 词条 `Priya` | 用户想要的标准写法 | 第 1 步 |
| 别名 `Preeya` | 识别常写成的样子 | 第 1 步 |
| `UpdatedAt` | 词条最近一次修改的时间 | 本步 `dict.go:95` |
| `ASRHints` | 是否把词条发去语音模型 | 词典设置 |

### 为什么别名不发

别名是「识别本来就会写错的那个样子」。把它当提示发给识别器，等于告诉它「往这个方向写」，反而把错误钉死。提示只放正确词条。

### 边界

有些识别服务只收几十条提示，`dict.Hints` 的注释说它们会从列表末尾删。截尾保留列表前面的词条，所以按最近改过优先排时，新词条最能保住。

### 接下来

下一步看识别完的文字怎样把别名换回来。

## 第 4 步 · 别名在清理之前换回词条

> **一句话：** 识别出文字后，启用的别名在任意清理之前就被换回词条，所以不依赖语言模型。

### 图上是什么

- 橙色框是识别结果 `call Preeya.`。
- 箭头指向蓝色框，替换后是 `call Priya.`。
- 再往右是**语言模型清理**：它收到的文字已经对了。
- 下面两块：左边是匹配规则；右边虚线框说「模型关了或失败时」结果仍是 `call Priya.`。

### 匹配规则

`dict.Replace` 只看启用的词条（`Voxt/internal/dict/alias.go:25`）：

- 拉丁别名按**整词**匹配、不分大小写；两端是字母或数字时才算一个词（`wordRune`，`alias.go:192`）。
- 中文、日文、韩文别名可以在任意位置匹配，因为它们的词之间不写空格。
- 同一起点有多个可匹配时，**最长**的那个胜出（模式先按长度降序排，`alias.go:73`）。
- 已经按词条写好的原文不动，所以再跑一次也不会改坏（`alias.go:90`）。

$$\text{替换}(\text{Preeya}) = \text{Priya}\quad\text{当词典启用且别名启用}$$

| 符号 | 是什么 | 从哪来 |
|---|---|---|
| 识别结果 | 语音模型写出的文字 | 第 3 步的语音模型 |
| 别名 | 要被替换掉的写法 | 第 1 步 |
| 词条 | 替换成的正确写法 | 第 1 步 |

### 为什么不受模型影响

只用别名、不靠模型的这条路径，好处是「模型没来或报错」时结果仍然对。`spoken()` 在 `session/cleanup.go:68` 调用 `dict.Replace(raw, r.terms)`；`session/run.go:301` 先把识别原话交给它，`run.go:312` 才进入清理。顺序就是这样保证的。

### 接下来

替换只改别名。若识别器写出了一个既不是词条、也不在任何别名里的错法，就得靠下一步的术语表提醒语言模型。

## 第 5 步 · 术语表放在哪条消息里

> **一句话：** 小词典把术语表放在 system；大词典只挑选中的词条，放在 user 开头，然后才是这次请求的输入。

### 图上是什么

- 左面板是不超过 30 个不同词条：system 里有通用规则和 `- Priya (heard as: Preeya)`，user 里是 `call Priya.`。
- 右面板是超过 30 个不同词条：system 只有通用规则；user 先放 `<glossary>`，再写 `call Priya.`。
- 两个 user 都用 `call Priya.`，因为第 4 步已把 `Preeya` 换成 `Priya`，语言模型收到的是替换后的文字（`session/run.go:301-312`）。
- 底部说明候选、两个上限和缓存边界：先成为候选，再取最长前缀；provider 可能复用未变的 system，不保证省时或省 token。

### 候选和发送位置

`compose.Build` 先按大小写去重，再按不同词条数选择候选（`Voxt/internal/compose/compose.go:366-377`、`585-599`）：

| 不同词条数 | 候选 | system | user |
|---|---|---|---|
| $n \le 30$ | 全部不同词条，保持词典顺序 | 通用规则 + 渲染后的术语表 | 替换后的输入 |
| $n > 30$ | 只挑替换后的文字提到的词条或别名 | 只有通用规则 | 有匹配时，先放 `<glossary>`，再放替换后的输入 |

大词典没有匹配时，user 开头没有 `<glossary>` 块，system 的通用规则仍在（`compose.go:411-416`）。

### 公式

$$C = \begin{cases}\text{全部不同词条} & n \le 30 \\\text{文字提到的词条} & n > 30\end{cases}$$

$$G = \text{满足 } |G| \le 60 \text{ 且 } B(G) \le 2000 \text{ 的 } C \text{ 的最长前缀}$$

$$B(G) = \sum_{g \in G}(\operatorname{bytes}(g) + 1)$$

| 符号 | 是什么 | 从哪来 |
|---|---|---|
| $n$ | 去重后的启用词条数 | `distinctTerms`，`compose.go:585-599` |
| $C$ | 按词典顺序排好的候选行 | 本步的选择规则 |
| $G$ | 实际发送的连续前缀 | `compose.go:576-580` |
| $g$ | 一条完整术语表行 | `- Term (heard as: alias)` |
| $\operatorname{bytes}(g)$ | 这一行的 UTF-8 字节数 | Go 的 `len(string)` |
| $B(G)$ | 行内容和换行分隔的字节数，不含 `<glossary>` 标签 | `compose.go:576-580` |
| 30 / 60 / 2000 | 整份候选阈值 / 行数上限 / 字节上限 | `compose.go:244-250` |

循环遇到首个放不下的行就 `break`。它不跳过该行去找更短的行，也不把任何一行截成两半。

### 代入图上的数

构造一个三条候选的例子，每行都是 900 字节：

| 候选行 | 加入后的字节数 | 结果 |
|---|---|---|
| 第 1 行 | $900 + 1 = 901$ | 留下 |
| 第 2 行 | $901 + 900 + 1 = 1802$ | 留下 |
| 第 3 行 | $1802 + 900 + 1 = 2703$ | 超过 2000，停止 |

所以 $G$ 只有前两条完整行。若第 61 行才超出行数上限，也同样在第 60 行后停止。

### 缓存能保证什么

小词典的术语表位于 system，且 system 不随本次听写文字变化。其他设置也不变时，provider **可能**复用这个未变前缀的 prompt 缓存；测试只保证 system 字符串不随输入变化（`compose_test.go:574-577`、`595-630`）。这不保证缓存命中、保留、省时或省 token。

### 边界

术语表只影响语言模型的输出；它不改识别结果，也不保证模型一定照做。术语表开关关掉时，`glossary()` 返回空（`run_transcribe.go:110-112`）。

### 接下来

词条和别名都讲完了。下一步是另一处设置里的全词典备注，以及 system、history、user 的完整顺序。

## 第 6 步 · 全词典备注和完整消息顺序

> **一句话：** 整部词典的 `settings.Dictionary.Notes` 作为单独一层进 system；这次请求的输入只在 user，行内备注仍然私有。

### 图上是什么

- 左边蓝色框是**全词典备注**，来源写成 `settings.Dictionary.Notes`，例如「Priya 在设计团队；团队念成 Preeya」。
- 箭头指向右边 system 提示的备注一层。这里明确写着：这次请求的输入不在 system。
- 下方橙色框列出**从不发到**的两个地方：语音模型、文字稿替换。
- 底部先给消息顺序 `system → history → user`，再说关掉备注能挡住全词典备注。

### 两种备注不是一回事

行内的 `store.Term.Note` 是私有备注，源码明确写着「不发送到任何地方」（`internal/store/store.go:215-230`）。本步讲的是另一处 `settings.Dictionary.Notes`：整部词典共用的一段 Markdown，只给语言模型看。

`PromptDictionary` 只在 `Dictionary.Enabled && !NotesOff` 时返回这段全词典备注（`Voxt/internal/session/text.go:120-126`）。`addDictionary` 去掉首尾空白，把它作为 `dictionary` 一层加在任务说明之后、scene 和术语表之前（`Voxt/internal/compose/dictionary.go:11-17`）。层与层之间用空行连接。

### 公式

$$\text{system} = [\text{任务层},\ \text{全词典备注},\ \text{scene},\ \text{小词典术语表（如有）}]$$

$$\text{messages} = [\text{system},\ \ldots\text{history},\ \text{user}]$$

$$\text{user} = [\text{大词典的 } \langle glossary\rangle\text{（如有）}] \oplus [\langle input\rangle\text{call Priya.}\langle/input\rangle]$$

| 符号 | 是什么 | 从哪来 |
|---|---|---|
| 全词典备注 | 整部词典共用的 `settings.Dictionary.Notes` | `session/text.go:120-126` |
| scene | 当前任务的其他上下文层 | `compose/dictionary.go:11-17` 的位置关系 |
| 小词典术语表 | 第 5 步中不超过 30 个词条时放在 system 的内容 | 第 5 步 |
| messages | 发给语言模型的完整消息序列 | `compose.go:253-258` |
| history | system 和 user 之间的历史消息；本 Transcribe 示例为空 | `compose.go:253-258`、`387-392` |
| user | 最后一条用户消息 | `compose.go:253-258` |
| $\langle input\rangle$ | 包住这次请求替换后输入的标签 | `compose/before.go:13-17` |
| `call Priya.` | 第 4 步替换后的请求输入 | 第 4、5 步 |

### 为什么全词典备注和术语表不同

术语表是结构化的「词条 → 别名」，由程序按规则挑；全词典备注是自由文字，你说什么模型读什么。它能放术语表放不下的说明，比如「这个团队把 Priya 念成 Preeya，别改他们的说法」。它只给语言模型看，所以不会改变识别，也不会在文字稿里做替换。

### 边界

关掉备注开关只挡住提示，不删掉已经写的文字。全词典备注为空时这一层不加，system 和没有备注时一样。其他任务可以有 history；本章的 Transcribe 示例没有，它的清理示例位于 system，而不是 history（`compose.go:387-392`）。

### 接下来

四个去处讲完。最后一步盘点：语言模型不在时，哪些还管用。

## 第 7 步 · 没有语言模型时还剩什么

> **一句话：** 语音提示和别名替换在语言模型之外运行，模型关掉或失败也还在；术语表和全词典备注会一起消失。

### 图上是什么

- 四行分别列出语音提示、别名替换、术语表、全词典备注，每行有一个来往处说明。
- 右边橙色列是「模型关掉」时的状态：前两行 ✓，后两行 ✗。
- 下面两行说前两者在语言模型之外运行，模型失败也还在；词典总开关一关，四个都不走。
- 底部虚线框把话题交给下一章：录音和历史留多久。

### 为什么前两个还在

`SpeechHints` 只在发送识别请求时调用 `dict.Hints`（`session/run_audio.go:36`），`spoken()` 只在送清理之前调用 `dict.Replace`（`session/cleanup.go:68`）。两者都不需要语言模型。术语表由 `glossary()` 组装，全词典备注由 `addDictionary` 加进 system，两处都只在组装清理请求时才用；没有模型就没有这份请求。

| 去处 | 模型关掉时 | 原因 |
|---|---|---|
| 语音提示 | 仍在 | 发给识别器，不经过语言模型 |
| 别名替换 | 仍在 | 识别完立刻换，早于清理 |
| 术语表 | 消失 | 随语言模型提示一起发 |
| 全词典备注 | 消失 | 随语言模型消息一起发 |

### 总开关

`Dictionary.Enabled` 关掉时，`SpeechHints`、`spoken()`、`glossary()`、`PromptDictionary` 都返回空，四个去处一起停。其余三个开关（语音提示、术语表、关闭备注）各管一处。

### 接下来

词典只把文字写对。那次录音和它的历史还在，下一章看它们保留多久、怎样到期。
