## 第 1 步 · prompt 是一个字符串

> **一句话：** 推理的输入是一个 24 个字符的字符串；模型不接收字符，所以第一件事是把它变成数字。

### 图上是什么

- 标签 `PROMPT` 和一个白色方框：字符串 `"The capital of France is"`，共 24 个字符（含 4 个空格）。

### 背景

模型是一个函数：输入一串整数（token id），输出对「下一个 token」的分数。字符串不能直接送进去，第 2 步先把它变成 id。

本章后面用同一套记号，每一步都用上一步的产出：

| 符号 | 是什么 | 从哪来 |
|---|---|---|
| id | 一个 token 在词表里的编号，一个整数 | 第 2 步 |
| $s_t$ | 前向传播给词表里 token $t$ 的分数 | 第 3 步 |
| $p(t)$ | 由 $s_t$ 算出的概率 | 第 4 步 |

### 接下来

第 2 步：tokenizer 把字符串切成 token，每个换成一个 id。

## 第 2 步 · 切成 token，每个是一个整数 id

> **一句话：** tokenizer 把字符串切成 5 个 token，到词表里查出 5 个 id。

### 图上是什么

- 五个蓝色方框：5 个 token，`The`、`␣capital`、`␣of`、`␣France`、`␣is`。`␣` 表示开头的空格，空格属于这个 token。
- 方框下的数字：每个 token 的 id。
- 底部脚注：Llama-3 还会在最前面加一个 `<|begin_of_text|>`（id 128000），图上省略，让数目保持为 5。

### 代入图上的数

| 位置 | token | id |
|---|---|---|
| 1 | `The` | 791 |
| 2 | `␣capital` | 6864 |
| 3 | `␣of` | 315 |
| 4 | `␣France` | 9822 |
| 5 | `␣is` | 374 |

Llama-3 的词表有 128,256 项，所以每个 id 都是 0 到 128,255 之间的整数。

### 怎么切

- 切分依据是 tokenizer 训练时学到的词表，不是按空格切。常见的词是一个 token，少见的词会被切成几段。
- 同一个字符串总是得到同样的 id。所以后面第 6、9 步里，前 5 列每轮拿到的输入都一样。

### 词表为什么是 128,256 项

不是训练数据里有多少个不同的词，而是训练 tokenizer 时**事先定好的目标大小**：

1. 起点是 256 个字节（UTF-8 里一个字节的全部取值）。任何文本都能写成这 256 种字节的序列。
2. 在一大批文本上数「哪两个相邻片段一起出现得最多」，把它们合成一个新 token 加进词表。例如 `t`+`h` → `th`，再 `th`+`e` → `the`，再 `␣`+`the` → `␣the`。
3. 重复合并，直到词表到达目标大小。Llama-3 的目标是 128,000 个普通 token。

这种做法叫 BPE（byte pair encoding）。训练数据决定**合并出哪些** token（常见的词、词根、中文常用字），不决定**有多少**个。

另外 256 个是特殊 token，id 从 128,000 开始：`<|begin_of_text|>` 是 128000（上面脚注），第 10 步的 `<EOS>` 是 128001，其余大多是预留位。所以 128,000 + 256 = 128,256。

### 没见过的词怎么办

不会查不到。词表里没有整词，就切成词表里有的更小的片段；最坏情况切到单个字节，而 256 个字节都在词表里。所以任何字符串都能变成 id，不存在「未知词」。

代价是：一个生造的词、一段少见的语言，会被切成很多个 token，序列变长，后面每一步的计算和 KV cache（第 3 章）都跟着变多。

### 接下来

第 3 步把这 5 个 id 送进模型。

## 第 3 步 · 前向传播：每个词表 token 一个分数

> **一句话：** 5 个 id 一起进入 transformer，做一次前向传播，输出 128,256 个分数 $s_t$。

### 图上是什么

- 序列方框闪烁、连线变成流动的蓝色虚线：这 5 个 id 正在输入。
- 中间的方框 `transformer`，下面写着 `正在处理 5 个 token…`。

### 输出

| 符号 | 是什么 | 大小 | 从哪来 |
|---|---|---|---|
| $t$ | 词表里的一个 token，用 id 表示 | 0 到 128,255 | 第 2 步的词表 |
| $s_t$ | 模型给 $t$ 的分数，越大越可能是下一个 token | 一个实数 | 本步 |

一共 128,256 个分数：$s_0, s_1, \dots, s_{128255}$。例如 $s_{12366}$ 是 `␣Paris`（id 12366）的分数。

### 要点

- 模型在 5 个位置上都有计算，但选下一个 token 只用**最后一个位置**（`␣is`）的分数。
- $s_t$ 还不是概率：可以是任意实数，可正可负，加起来也不等于 1。
- 「前向传播」就是数据从模型的第一层流到最后一层的一次计算；第 2 章打开其中一层看里面做了什么。

### 接下来

第 4 步用 softmax 把分数变成概率。

## 第 4 步 · softmax 把分数变成概率，选一个

> **一句话：** softmax 把 128,256 个分数变成加起来等于 1 的概率；`␣Paris` 最大，选中它。

### 图上是什么

- 标签 `p(next token | sequence)`：给定当前序列，下一个 token 的概率，就是下面公式里的 $p(t)$。
- 四根柱子：概率最高的 4 个 token；选中的 `␣Paris` 是橙色，其余灰色。柱长正比于概率。
- `← 选中`：标出被选的那一个。

### 公式

$$
p(t) = \frac{e^{s_t}}{\sum_{u=0}^{128255} e^{s_u}}
$$

| 符号 | 是什么 | 从哪来 |
|---|---|---|
| $s_t$ | token $t$ 的分数 | 第 3 步 |
| $u$ | 求和变量，遍历词表里全部 128,256 个 token | |
| $e^{x}$ | 指数函数，$e \approx 2.718$；结果总是正数 | |
| $p(t)$ | token $t$ 是下一个 token 的概率 | 本步 |

每个 $e^{s_t}$ 都是正数，再除以它们的总和，所以每个 $p(t)$ 在 0 和 1 之间，全部加起来等于 1。

### 代入图上的数

| token | $p(t)$ |
|---|---|
| `␣Paris` | **0.82** |
| `␣Lyon` | 0.05 |
| `␣a` | 0.04 |
| `␣the` | 0.03 |
| 其余 128,252 个 | 合计 0.06 |

两个概率之比只取决于分数之差，分母约掉了：

$$
\frac{p(\text{Paris})}{p(\text{Lyon})} = e^{\,s_{\text{Paris}} - s_{\text{Lyon}}} = \frac{0.82}{0.05} = 16.4
$$

所以 $s_{\text{Paris}}$ 比 $s_{\text{Lyon}}$ 高 $\ln 16.4 \approx 2.8$。

### 怎么选

- **贪心：** 取概率最大的，选中 `␣Paris`。
- **采样：** 按概率抽一个，抽中 `␣Paris` 的机会是 0.82。SGLang 的默认采样参数（temperature 1.0、top_p 1.0）就是直接按这个分布抽。

### 接下来

第 5 步把选中的 token 接到序列末尾。

## 第 5 步 · 追加：输出变成输入

> **一句话：** `␣Paris`（id 12366）接到序列末尾，序列变成 6 个 id。

### 图上是什么

- 橙色的第 6 个方框 `␣Paris` 从下方飞入序列；橙色表示模型生成的 token，蓝色是 prompt 里的。
- 标签变成 `序列（6 个 token）`。

### 代入图上的数

序列现在是 791、6864、315、9822、374、12366。

### 自回归

「自回归」就是这个意思：每个新 token 都由「包含之前所有已生成 token」的序列来预测。

图上的循环除了 id 本身，不保留第 3 步算出的任何东西。所以下一次前向（第 6 步）要输入全部 6 个 id，前 5 个位置会被重新计算。

### 接下来

第 6 步对 6 个 id 再做一次前向。

## 第 6 步 · 再做一次前向，仍是全部 6 个

> **一句话：** 第 2 轮输入 6 个 id，前 5 个位置和第 3 步的输入、权重都一样，算出的结果也一样。

### 图上是什么

- 6 个方框一起闪烁，`transformer` 方框写着 `正在处理 6 个 token…`：6 个位置都在算。

### 哪些是重复的

| 位置 | 输入 id | 和第 3 步比 |
|---|---|---|
| 1–5 | 791、6864、315、9822、374 | id 相同、权重相同，结果相同 |
| 6 | 12366 | 新的 |

这一轮输出一组新的 $s_t$，取的是最后一个位置 `␣Paris` 的分数。

第 1 轮算 5 个位置，第 2 轮算 6 个，其中 5 个是在重做第 3 步已经做过的工作。为什么前 5 个位置的结果一定不变，第 2 章第 11 步在一层里面说明。

### 接下来

第 7 步对这组新分数再选一次。

## 第 7 步 · 再选一次

> **一句话：** 对第 2 轮的分数做同样的 softmax，`.` 最大，选中它。

### 图上是什么

- 新的四根柱子，`.` 是橙色（被选中），其余灰色。

### 代入图上的数

公式和第 4 步相同，$p(t) = e^{s_t} / \sum_u e^{s_u}$，只是 $s_t$ 换成第 6 步的新分数。

| token | $p(t)$ |
|---|---|
| `.` | **0.71** |
| `,` | 0.15 |
| `␣and` | 0.06 |
| `!` | 0.02 |
| 前 4 个合计 | 0.94 |

贪心选中 `.`，id 13。

### 为什么分布变了

输入变了：序列现在以 `␣Paris` 结尾。模型唯一的输入是这串 id，它不保留第 1 轮的任何状态，所以每轮都要把整串 id 重新传进去。

### 接下来

第 8 步把 `.` 接到序列末尾。

## 第 8 步 · 追加

> **一句话：** `.`（id 13）接到序列末尾，序列变成 7 个 id。

### 图上是什么

- 橙色的第 7 个方框 `.` 飞入序列，标签变成 `序列（7 个 token）`。

### 代入图上的数

序列现在是 791、6864、315、9822、374、12366、13。

### 每轮都是同样三步

| 轮 | 前向 | 选择 | 追加 | 序列长度 |
|---|---|---|---|---|
| 1 | 第 3 步 | 第 4 步 | 第 5 步 | 5 → 6 |
| 2 | 第 6 步 | 第 7 步 | 第 8 步 | 6 → 7 |
| 3 | 第 9 步 | 第 10 步 | 第 11 步（停止） | 7 |

轮与轮之间唯一的区别是序列长度。

### 接下来

第 9 步做第 3 轮前向。

## 第 9 步 · 第 3 轮前向，7 个位置

> **一句话：** 第 3 轮输入 7 个 id；前 5 个位置第三次算，`␣Paris` 第二次算。

### 图上是什么

- 7 个方框一起闪烁，`transformer` 方框写着 `正在处理 7 个 token…`。

### 公式

prompt 有 $P$ 个 token 时，第 $r$ 轮输入 $P + r - 1$ 个 id，就要算这么多个位置。$N$ 轮加起来：

$$
\sum_{r=1}^{N} (P + r - 1) = N P + \frac{N(N-1)}{2}
$$

| 符号 | 是什么 | 图上的值 | 从哪来 |
|---|---|---|---|
| $P$ | prompt 的 token 数 | 5 | 第 2 步 |
| $r$ | 第几轮（每轮生成一个 token） | 1、2、3 | |
| $N$ | 总轮数 = 生成的 token 数 | 3 | 第 3–11 步 |

### 代入图上的数

| 轮 $r$ | $P + r - 1$ |
|---|---|
| 1 | 5 |
| 2 | 6 |
| 3 | 7 |
| 合计 | $3 \times 5 + \frac{3 \times 2}{2} = 15 + 3 = 18$ |

### 增长得多快

- $NP$ 这部分随「prompt 长度 × 输出长度」增长。
- $N(N-1)/2$ 这部分随输出长度的平方增长。

### 接下来

第 10 步：这一轮最大的是 `<EOS>`。

## 第 10 步 · 这次选中 EOS

> **一句话：** 第 3 轮 softmax 后概率最大的是 `<EOS>`（id 128001），它是词表里普通的一项。

### 图上是什么

- 四根柱子，`<EOS>` 是红色（被选中），其余灰色。红色在本章表示 EOS。

### 代入图上的数

| token | $p(t)$ |
|---|---|
| `<EOS>` | **0.88** |
| `␣It` | 0.05 |
| `␣The` | 0.03 |
| `\n` | 0.02 |
| 前 4 个合计 | 0.98 |

### EOS 是什么

- `<EOS>` = end of sequence，Llama-3 里写作 `<|end_of_text|>`，id 128001。
- 模型在训练中学会了在回答完整时给它高分。
- 选法和 `␣Paris`、`.` 一样：$p(t)$ 最大。循环只在选中之后才区别对待它。

### 接下来

第 11 步：选中 EOS 后循环停止。

## 第 11 步 · 停止，把 id 解码回文本

> **一句话：** 选中 id 128001 后循环结束；tokenizer 把 id 转回文本，生成的部分是 `" Paris."`。

### 图上是什么

- 红色的第 8 个方框 `<EOS>` 接在序列末尾。
- 红框里的 `输出： " Paris."`：生成部分解码后的文本，不含 `<EOS>`。
- 底部脚注：SGLang 让 request 停下的其他条件。

### 代入图上的数

生成的 id 是 12366、13、128001。解码时去掉 `<EOS>`，12366、13 → `" Paris."`。SGLang 的 `skip_special_tokens` 默认是 `True`，`<EOS>` 这类特殊 token 不出现在输出文本里。

### request 什么时候停

SGLang 每生成一个 token 检查一次，哪个条件先到就停在哪里：

| 条件 | SGLang 参数 | 默认 |
|---|---|---|
| 模型输出 EOS | （设 `ignore_eos=True` 可关掉） | 开 |
| 生成的 token 数到上限 | `max_new_tokens` | 128 |
| 输出里出现指定字符串 | `stop` | 无 |
| 生成了指定的 token id | `stop_token_ids` | 无 |

这就是推理的全部：分词，然后前向、选择、追加，直到停止。

### 接下来

第 12 步把三轮的计算量加起来。

## 第 12 步 · 算总账

> **一句话：** 为 3 个新 token 算了 18 个位置，其中 11 个是用同样的输入重算已经算过的列。

### 图上是什么

- 三行格子，每轮一行；每个格子对齐在它算的那一列 token 下面。蓝色是 prompt 列，橙色是生成的 token。
- 每行右边：`第 1 轮 · 5 个位置`、`第 2 轮 · 6 个位置`、`第 3 轮 · 7 个位置`。
- 下方：`5 + 6 + 7 = 18 个位置被计算`、`生成 3 个 token`，以及「这 5 个 prompt 列：输入相同，输出相同，算了 3 遍」。

### 代入图上的数

总数就是第 9 步的 $NP + N(N-1)/2$，$P = 5$、$N = 3$，等于 18。

| | 位置数 | 是哪些 |
|---|---|---|
| 第一次算 | 7 | 第 1 轮的 5 个 prompt 列、第 2 轮的 `␣Paris`、第 3 轮的 `.` |
| 重算 | 11 | prompt 列在第 2、3 轮各 5 次，`␣Paris` 在第 3 轮 1 次 |
| 合计 | 18 | |

如果每列第一次算完就把结果留下，三轮只需算 $5 + 1 + 1 = 7$ 个位置。

### 接下来

图上的问题是：后面的位置到底需要一列计算结果里的哪一部分？第 2 章打开一层来找答案。
