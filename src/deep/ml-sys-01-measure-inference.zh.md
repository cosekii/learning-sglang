## 第 1 步 · 量首个 token 前的等待

**一句话。** TTFT 告诉你：用户要等多久，才能看到回答的第一个 token。

**图上是什么。** 左边时钟在请求发出时是 0 ms；右边时钟在首个 token 出现时是 250 ms。蓝色只标这两个时刻之间的等待。这个例子的等待包含排队与 prefill，但图中没有把两者分别测成多少毫秒。

**公式与符号。**

$$\mathrm{TTFT}=t_{\mathrm{first\ token}}-t_{\mathrm{request\ sent}}$$

- $\mathrm{TTFT}$：time to first token，也就是首个 token 前的等待。
- $t_{\mathrm{request\ sent}}$：请求发出的时刻，图中是 0 ms。
- $t_{\mathrm{first\ token}}$：首个输出 token 出现的时刻，图中是 250 ms。
- $\mathrm{ms}$：毫秒；$1{,}000\ \mathrm{ms}=1$ 秒。

**代入图上的数。**

$$\mathrm{TTFT}=250-0=250\ \mathrm{ms}=0.250\ \mathrm{s}=\frac14\ \mathrm{s}$$

250 ms 是 zero-to-sglang 第 1 部分第 5 章 §3.1 的构造教学值，不是本机实测。《Inference Engineering》§1.4 使用同样的测量边界：从请求发出到首个输出 token 出现。本步没有分别测量排队、prefill 和后续回答各花多久。

**接下来。** 首个 token 已经出现；下一把尺子要量相邻输出 token 之间的间隔。

## 第 2 步 · 量相邻 token 的间隔

**一句话。** ITL 是相邻两个输出 token 出现时刻的差，每一段都可以单独测量。

**图上是什么。** 从请求发出开始计时，同一个请求的第 1 至第 4 个输出 token 分别在 250、275、295、325 ms 出现。三段蓝色箭头分别标出 25、20、30 ms；蓝色只表示 ITL，不包括首个 token 前的 TTFT。

**公式与符号。**

$$\mathrm{ITL}_i=t_i-t_{i-1}\quad(i=2,3,4)$$

- $\mathrm{ITL}_i$：inter-token latency，第 $i$ 个输出 token 与前一个输出 token 的间隔。
- $t_i$：第 $i$ 个输出 token 出现的时刻；$t_1$ 是第 1 步首个 token 的 250 ms。
- $i$：输出 token 的编号，从 1 开始；本步量第 2、3、4 个 token 前的三段间隔。
- $\mathrm{ms}$：毫秒，沿用上一步的单位。

**代入图上的数。**

$$\mathrm{ITL}_2=275-250=25\ \mathrm{ms}$$

$$\mathrm{ITL}_3=295-275=20\ \mathrm{ms}$$

$$\mathrm{ITL}_4=325-295=30\ \mathrm{ms}$$

zero-to-sglang 第 1 部分第 5 章 §3.1 与《Inference Engineering》§1.4 都把 ITL 定义为相邻输出 token 的时间间隔。第 2 至第 4 个时刻是在同一构造请求上补写的教学值，不是本机实测；三段间隔不必一样长。

**接下来。** 三段间隔已经分别量出；下一步把它们合成一个平均值。

## 第 3 步 · 求首个 token 后的平均间隔

**一句话。** TPOT 把首个 token 后的各段 ITL 合成一个平均值。

**图上是什么。** 同一个请求仍有 250、275、295、325 ms 四个时刻，以及 25、20、30 ms 三段蓝色 ITL。本步把三段间隔一起取平均；首末时刻也算出同一个结果。TPOT 不含第 1 步的 TTFT，平均也不表示三段间隔变得一样长。

**公式与符号。**

$$\mathrm{TPOT}=\frac{\sum_{i=2}^{N}\mathrm{ITL}_i}{N-1}=\frac{t_N-t_1}{N-1}\quad(N\ge2)$$

- $\mathrm{TPOT}$：time per output token；本例是首个 token 之后，每段相邻输出间隔的平均值。
- $N$：输出 token 的总数，本例为 4；$N-1$ 才是首个 token 后的间隔数。
- $\mathrm{ITL}_i$：第 2 步量出的第 $i$ 个 token 与前一个 token 的间隔。
- $t_1$、$t_N$：第 1 个和最后一个输出 token 的时刻，本例分别为 250、325 ms。
- $\sum_{i=2}^{N}$：从第 2 个 token 到第 $N$ 个 token，把各段 ITL 加起来。

**代入图上的数。**

$$\mathrm{TPOT}=\frac{25+20+30}{4-1}=\frac{75}{3}=25\ \mathrm{ms}$$

$$\mathrm{TPOT}=\frac{325-250}{4-1}=\frac{75}{3}=25\ \mathrm{ms}$$

zero-to-sglang 第 1 部分第 5 章 §3.1 用同样的边界：输出 200 个 token 时，扣除首个 token 后按 199 段计算，课程常把单位写成 ms/token。本例的 25 ms 恰好等于第一段 ITL，但另外两段仍是 20、30 ms；请求发出到首个 token 的 250 ms TTFT 没有进入分子。

**接下来。** 首个 token 前的等待和后续平均间隔都已量出；下一步可以量整个回答从头到尾的总时间。

## 第 4 步 · 量请求的完整时间

**一句话。** E2E 总延迟从请求发出算到请求完成，把首个 token 前和后的时间都算进去。

**图上是什么。** 请求在 0 ms 发出，第 1 个 token 在 250 ms 出现，第 4 个也是最后一个 token 在 325 ms 出现，请求随即完成。上方蓝线量完整路线；下方两段分别标出 TTFT 的 250 ms 和首个 token 后的 75 ms。75 ms 仍是第 2 步三段 ITL 的总和，不是只取一段，也不是只加一次平均 TPOT。

**公式与符号。**

$$\mathrm{E2E}=t_{\mathrm{complete}}-t_{\mathrm{request\ sent}}=\mathrm{TTFT}+\sum_{i=2}^{N}\mathrm{ITL}_i$$

- $\mathrm{E2E}$：end-to-end latency，从请求发出到全部完成的总延迟。
- $t_{\mathrm{request\ sent}}$：请求发出的时刻，图中是 0 ms。
- $t_{\mathrm{complete}}$：请求完成的时刻；本例把最后一个 token 出现的 325 ms 视为完成时刻。
- $\mathrm{TTFT}$：第 1 步量出的首 token 前等待，本例为 250 ms。
- $\sum_{i=2}^{N}\mathrm{ITL}_i$：从第 2 个到第 $N$ 个 token，把所有相邻间隔相加；本例 $N=4$。

**代入图上的数。**

$$\mathrm{E2E}=325-0=325\ \mathrm{ms}$$

$$\mathrm{E2E}=250+(25+20+30)=250+75=325\ \mathrm{ms}$$

zero-to-sglang 第 1 部分第 5 章 §3.1 将 E2E 定义为请求从发出到全部完成的总时长，并用 $\mathrm{E2E}=\mathrm{TTFT}+\text{剩余生成时间}$ 计算。本例沿用同一边界；0、250、325 ms 都是构造教学值，不是本机实测，也没有另列最后 token 之后的处理时间。

**接下来。** 一个请求的完整时间已经量出；下一步把多个请求放在一起，找出其中较慢的请求。

## 第 5 步 · 排队找出 P50 与最慢请求

**一句话。** 把 100 个请求的 E2E 总延迟从短到长排队，就能读出排在中间的 P50，也能单独看到最慢请求。

**图上是什么。** 每根蓝色柱子是一个请求的 E2E 总延迟：前 51 根都是 200 ms，接着 48 根都是 300 ms，最后一根是 2000 ms。下方卡片标出第 50、100 个请求；最慢请求的 2000 ms 是 P50 的 10 倍。

**公式与符号。** 本步把排在 50% 位置的总延迟叫 P50：

$$L_{(1)}\le L_{(2)}\le\cdots\le L_{(N)},\qquad r=\lceil0.50N\rceil,\qquad \mathrm{P50}=L_{(r)}$$

- $L_{(i)}$：排队后第 $i$ 个请求的 E2E 总延迟；每个请求的量法来自第 4 步。
- $N$：请求总数；本例为 $51+48+1=100$。
- $r$：排到 50% 时的位置；$\lceil\ \rceil$ 表示向上取整。
- $\mathrm{P50}$：排在 $r$ 位置的总延迟，不是这些请求的平均值。

**代入图上的数。**

$$\mathrm{P50}=L_{(\lceil0.50\times100\rceil)}=L_{(50)}=200\ \mathrm{ms}$$

$$L_{(100)}=2000\ \mathrm{ms}=10\times200\ \mathrm{ms}=10\times\mathrm{P50}$$

另一种常见算法会把第 50、51 个等待取平均；本例两数都是 200 ms，所以结果仍为 200 ms。三个数组成 51、48、1 个请求的构造分布，沿用 zero-to-sglang 第 1 部分第 5 章 §5.2 的「99 个请求在 100–300 ms、1 个请求为 2 s」情境，不是本机实测。课程 §5.1 和《Inference Engineering》§1.4.1 都把 P50 放在排队中间。其他数据集或工具可能用插值求 P50，本步不展开。

**接下来。** 排队中间的位置已经找到；下一步再看第 99 个请求，找找更靠后的等待。

## 第 6 步 · 排队找出 P99

**一句话。** P99 取排在 99% 位置的请求总延迟；本图是第 99 个请求的 300 ms，不是最慢请求的 2000 ms。

**图上是什么。** 100 根蓝色柱子和上一步相同：前 51 根为 200 ms，接着 48 根为 300 ms，最后 1 根为 2000 ms。下方卡片改标第 99、100 个请求。第 99 个是 300 ms，所以 100 个中有 99 个不超过 300 ms；最慢的第 100 个比 P99 多等 $2000-300=1700$ ms。

**公式与符号。** 本步沿用上一步的取位方法，把排在 99% 位置的总延迟叫 P99：

$$L_{(1)}\le L_{(2)}\le\cdots\le L_{(N)},\qquad r=\lceil0.99N\rceil,\qquad \mathrm{P99}=L_{(r)}$$

- $L_{(i)}$：排队后第 $i$ 个请求的 E2E 总延迟，与上一步相同。
- $N$：请求总数，本例为 100。
- $r$：排到 99% 时的位置；$\lceil\ \rceil$ 表示向上取整。
- $\mathrm{P99}$：排在 $r$ 位置的总延迟，不是平均值，也不必然等于最慢请求。

**代入图上的数。**

$$\mathrm{P99}=L_{(\lceil0.99\times100\rceil)}=L_{(99)}=300\ \mathrm{ms}$$

$$L_{(100)}-\mathrm{P99}=2000-300=1700\ \mathrm{ms}$$

zero-to-sglang 第 1 部分第 5 章 §5.1 要求同时观察 P50 和 P99，用 P99 看较慢的那部分请求；§5.2 用 99 个较快请求和 1 个 2 s 请求说明平均值会遮住那 1 个慢请求。本图的 51、48、1 个请求是据该情境构造的教学分布，不是本机实测。课程没有规定本图的取位公式；这里沿第 5 步明确使用向上取整，其他工具可能采用插值，本步不展开。

**接下来。** 中间和靠后的等待都已经量出；下一步改看同一段时间能完成多少个请求。
